
## 1. Middleware

### What is middleware?

**Middleware** is a function that runs **between** the incoming request and the final response. It can:

- read or modify `req` and `res`
- run any code (logging, auth checks, validation)
- end the request-response cycle (send a response)
- pass control to the next middleware with `next()`

```
Request --> [Middleware 1] --> [Middleware 2] --> [Route Handler] --> Response
              logger            auth check          sends data
```

### Anatomy

```js
const myMiddleware = (req, res, next) => {
  // do something with req / res
  next();   // pass control to the next function
};
```

|Argument|Purpose|
|---|---|
|`req`|Incoming request|
|`res`|Outgoing response|
|`next`|Function that moves to the next middleware/route|

> If a middleware neither calls `next()` nor sends a response, the request **hangs forever**.

### Your first middleware

```js
const express = require('express');
const app = express();

const logger = (req, res, next) => {
  console.log(`${req.method} ${req.originalUrl} - ${new Date().toISOString()}`);
  next();
};

app.use(logger);   // runs for every request

app.get('/', (req, res) => res.send('Home'));
app.get('/about', (req, res) => res.send('About'));

app.listen(3000);
```

Visiting `/` and `/about` prints:

```
GET / - 2026-10-28T10:15:00.000Z
GET /about - 2026-10-28T10:15:03.000Z
```

### Types of middleware

|Type|Description|Example|
|---|---|---|
|**Application-level**|Applies to the whole app|`app.use(logger)`|
|**Route-level**|Applies to a specific route|`app.get('/x', auth, handler)`|
|**Router-level**|Applies to an `express.Router()`|`router.use(auth)`|
|**Built-in**|Ships with Express|`express.json()`, `express.static()`|
|**Third-party**|Installed via npm|`cors`, `morgan`, `helmet`|
|**Error-handling**|Has 4 arguments `(err, req, res, next)`|Central error handler|

### Application-level middleware

```js
// runs on every request
app.use((req, res, next) => {
  console.log('Every request');
  next();
});

// runs only for paths starting with /api
app.use('/api', (req, res, next) => {
  console.log('API request');
  next();
});
```

### Route-level middleware

```js
const checkAdmin = (req, res, next) => {
  if (req.query.role !== 'admin') {
    return res.status(403).json({ error: 'Admins only' });
  }
  next();
};

app.get('/admin', checkAdmin, (req, res) => {
  res.send('Welcome, admin');
});

// multiple middleware on one route
app.get('/report', logger, checkAdmin, (req, res) => {
  res.send('Secret report');
});
```

### Router-level middleware

```js
const router = express.Router();

router.use(checkAdmin);   // applies to every route in this router

router.get('/stats', (req, res) => res.send('Stats'));
router.get('/users', (req, res) => res.send('All users'));

app.use('/admin', router);
```

### Order matters

Middleware runs **in the order it is defined**.

```js
app.use(logger);                 // 1st
app.use(express.json());         // 2nd

app.get('/', (req, res) => {     // 3rd
  res.send('Home');
});

app.use((req, res) => {          // last: 404 handler
  res.status(404).send('Not found');
});

app.use((err, req, res, next) => {   // very last: error handler
  res.status(500).send('Error');
});
```

Recommended order:

1. Security and logging (`helmet`, `cors`, `morgan`)
2. Body parsers (`express.json()`)
3. Routes
4. 404 handler
5. Error-handling middleware

### Passing data between middleware

Attach values to `req`:

```js
const addTimestamp = (req, res, next) => {
  req.requestTime = new Date().toISOString();
  next();
};

const fakeAuth = (req, res, next) => {
  req.user = { id: 1, name: 'Ali' };   // later: decoded from a JWT
  next();
};

app.use(addTimestamp);

app.get('/profile', fakeAuth, (req, res) => {
  res.json({ user: req.user, time: req.requestTime });
});
```

### Ending the cycle early

```js
const requireApiKey = (req, res, next) => {
  const key = req.get('x-api-key');

  if (!key || key !== process.env.API_KEY) {
    return res.status(401).json({ error: 'Invalid API key' });  // stops here
  }

  next();   // allowed through
};

app.use('/api', requireApiKey);
```

> Always use `return` before `res.json()` so the code after it doesn't also run.

### Built-in middleware

```js
app.use(express.json());                           // parse JSON body
app.use(express.urlencoded({ extended: true }));   // parse form body
app.use(express.static('public'));                 // serve static files
```

### Popular third-party middleware

```bash
npm install cors morgan helmet cookie-parser
```

```js
const cors = require('cors');
const morgan = require('morgan');
const helmet = require('helmet');
const cookieParser = require('cookie-parser');

app.use(cors());              // allow cross-origin requests (needed for React)

app.use(cookieParser());      // populate req.cookies
```

|Package|Purpose|
|---|---|
|`cors`|Enable Cross-Origin Resource Sharing|
|`morgan`|HTTP request logging|

|`cookie-parser`|Parse cookies|
|`express-rate-limit`|Limit requests per IP|
|`multer`|File uploads (later note)|

### Error-handling middleware

Has **four** parameters. Express recognises it by the `err` argument.

```js
app.get('/crash', (req, res, next) => {
  const err = new Error('Something broke');
  err.status = 500;
  next(err);                     // forwards to the error handler
});

// must be defined AFTER all routes
app.use((err, req, res, next) => {
  console.error(err.message);
  res.status(err.status || 500).json({
    success: false,
    message: err.message || 'Internal Server Error',
  });
});
```

Async errors (Express 4): wrap in try/catch and call `next(err)`.

```js
app.get('/data', async (req, res, next) => {
  try {
    const data = await someAsyncTask();
    res.json(data);
  } catch (err) {
    next(err);
  }
});
```

> Express 5 forwards rejected promises to the error handler automatically.

### Reusable async wrapper

```js
const asyncHandler = (fn) => (req, res, next) =>
  Promise.resolve(fn(req, res, next)).catch(next);

app.get('/data', asyncHandler(async (req, res) => {
  const data = await someAsyncTask();
  res.json(data);
}));
```

## 2. Body Parsing

### The problem

A request body arrives as a **raw stream of data**. Without parsing, `req.body` is `undefined`.

```js
app.post('/users', (req, res) => {
  console.log(req.body);   // undefined (no parser added)
});
```

### The solution: body-parsing middleware

```js
app.use(express.json());
app.use(express.urlencoded({ extended: true }));
```

Add these **before** your routes.

### `express.json()`

Parses bodies with `Content-Type: application/json`.

```js
app.use(express.json());

app.post('/api/users', (req, res) => {
  console.log(req.body);   // { name: 'Ali', age: 22 }
  res.status(201).json(req.body);
});
```

```bash
curl -X POST http://localhost:3000/api/users \
  -H "Content-Type: application/json" \
  -d '{"name":"Ali","age":22}'
```

### `express.urlencoded()`

Parses **HTML form** submissions (`application/x-www-form-urlencoded`).

```js
app.use(express.urlencoded({ extended: true }));

app.post('/login', (req, res) => {
  const { email, password } = req.body;
  res.send(`Email: ${email}`);
});
```

```html
<form action="/login" method="POST">
  <input type="email" name="email" />
  <input type="password" name="password" />
  <button type="submit">Login</button>
</form>
```

|Option|Meaning|
|---|---|
|`extended: true`|Uses the `qs` library, supports nested objects|
|`extended: false`|Uses `querystring`, flat key/value only|

### Content-Type decides the parser

|Content-Type|Parser needed|Sent by|
|---|---|---|
|`application/json`|`express.json()`|Axios, fetch, Postman (raw JSON)|
|`application/x-www-form-urlencoded`|`express.urlencoded()`|HTML forms|
|`multipart/form-data`|`multer`|File uploads|
|`text/plain`|`express.text()`|Plain text|

### Limiting body size

```js
app.use(express.json({ limit: '10kb' }));
```

Prevents huge payloads from overloading your server.

### Handling invalid JSON

Malformed JSON triggers an error. Catch it with error middleware:

```js
app.use(express.json());

// ... routes ...

app.use((err, req, res, next) => {
  if (err.type === 'entity.parse.failed') {
    return res.status(400).json({ error: 'Invalid JSON body' });
  }
  next(err);
});
```

### Body parsing vs the plain `http` module

```js
// Plain http: manual
let body = '';
req.on('data', (chunk) => (body += chunk));
req.on('end', () => {
  const data = JSON.parse(body);
});

// Express: one line
app.use(express.json());   // then use req.body
```

### Common mistakes

- Forgetting the `Content-Type: application/json` header in the client
- Placing `express.json()` **after** the routes
- Sending JSON but only using `express.urlencoded()`

## 3. REST API Fundamentals

### What is an API?

An **API** (Application Programming Interface) lets two programs talk to each other. A frontend (React) asks a backend (Express) for data, and the backend replies, usually as **JSON**.

### What is REST?

**REST** (Representational State Transfer) is a set of conventions for designing web APIs around **resources** using standard HTTP methods.

```
React App  ---- HTTP request (JSON) ---->  Express API  ---->  Database
React App  <---- HTTP response (JSON) ---  Express API  <----  Database
```

### Core principles

|Principle|Meaning|
|---|---|
|**Client-Server**|Frontend and backend are separate|
|**Stateless**|Each request carries everything needed (e.g. a token); server keeps no session memory|
|**Resource-based**|Everything is a resource identified by a URL (`/users`, `/products`)|
|**Uniform interface**|Use standard HTTP methods and status codes|
|**JSON representation**|Data usually exchanged as JSON|

### Resources and endpoints

A **resource** is a thing your API manages (user, product, post). An **endpoint** is a URL for it.

```
/api/users          <- collection of users
/api/users/5        <- one specific user
/api/users/5/posts  <- posts that belong to user 5
```

### HTTP methods map to CRUD

|CRUD|HTTP Method|Endpoint|Action|Success status|
|---|---|---|---|---|
|**C**reate|`POST`|`/api/users`|Add a new user|`201 Created`|
|**R**ead (all)|`GET`|`/api/users`|List users|`200 OK`|
|**R**ead (one)|`GET`|`/api/users/:id`|Get one user|`200 OK`|
|**U**pdate (full)|`PUT`|`/api/users/:id`|Replace a user|`200 OK`|
|**U**pdate (partial)|`PATCH`|`/api/users/:id`|Change some fields|`200 OK`|
|**D**elete|`DELETE`|`/api/users/:id`|Remove a user|`204 No Content`|

### PUT vs PATCH

```js
// existing user: { id: 1, name: 'Ali', email: 'ali@x.com', age: 22 }

// PUT: send the WHOLE object; missing fields are lost/replaced
// PATCH: send only the fields you want to change
PATCH /api/users/1   body: { "age": 23 }
```

### URL naming best practices

|Do|Don't|
|---|---|
|`/api/users` (plural nouns)|`/api/getUsers` (verbs in URL)|
|`/api/users/5`|`/api/user?id=5` for identifying a resource|
|`/api/users/5/posts` (nesting)|`/api/getUserPostsById/5`|
|lowercase, hyphens: `/api/blog-posts`|`/api/BlogPosts`, `/api/blog_posts`|
|Version it: `/api/v1/users`|No versioning|

> The **HTTP method** is the verb. The **URL** is the noun.

### Query strings for filtering, sorting, pagination

```
GET /api/products?category=phones         <- filter
GET /api/products?sort=price              <- sort
GET /api/products?page=2&limit=10         <- pagination
GET /api/products?search=iphone           <- search
```

### Status codes to use

|Code|Name|When|
|---|---|---|
|`200`|OK|Successful GET / PUT / PATCH|
|`201`|Created|Successful POST|
|`204`|No Content|Successful DELETE|
|`400`|Bad Request|Validation failed, malformed input|
|`401`|Unauthorized|Missing/invalid authentication|
|`403`|Forbidden|Logged in but not allowed|
|`404`|Not Found|Resource doesn't exist|
|`409`|Conflict|Duplicate (email already used)|
|`422`|Unprocessable Entity|Valid syntax, invalid data|
|`429`|Too Many Requests|Rate limit hit|
|`500`|Internal Server Error|Unexpected server bug|

### Consistent JSON response format

```json
// Success
{
  "success": true,
  "data": { "id": 1, "name": "Ali" }
}

// Success (list)
{
  "success": true,
  "count": 2,
  "data": [ { "id": 1 }, { "id": 2 } ]
}

// Error
{
  "success": false,
  "message": "User not found"
}
```

Using one format everywhere makes the frontend simpler.

### `controllers/productController.js`

```js
// temporary in-memory data
let products = [
  { id: 1, name: 'Laptop', price: 55000, category: 'electronics' },
  { id: 2, name: 'Headphones', price: 2500, category: 'electronics' },
  { id: 3, name: 'Notebook', price: 120, category: 'stationery' },
];

let nextId = 4;

// CREATE: POST /api/products
const createProduct = (req, res) => {
  const { name, price, category } = req.body;

  if (!name || price === undefined) {
    return res.status(400).json({
      success: false,
      message: 'Name and price are required',
    });
  }

  if (typeof price !== 'number' || price < 0) {
    return res.status(400).json({
      success: false,
      message: 'Price must be a positive number',
    });
  }

  const product = { id: nextId++, name, price, category: category || 'general' };
  products.push(product);

  res.status(201).json({ success: true, data: product });
};

// READ ALL: GET /api/products?category=&sort=&page=&limit=
const getProducts = (req, res) => {
  let result = [...products];
  const { category, search, sort, page = 1, limit = 10 } = req.query;

  // filter
  if (category) {
    result = result.filter((p) => p.category === category);
  }

  // search
  if (search) {
    result = result.filter((p) =>
      p.name.toLowerCase().includes(search.toLowerCase())
    );
  }

  // sort
  if (sort === 'price') result.sort((a, b) => a.price - b.price);
  if (sort === '-price') result.sort((a, b) => b.price - a.price);

  // pagination
  const total = result.length;
  const start = (Number(page) - 1) * Number(limit);
  result = result.slice(start, start + Number(limit));

  res.json({
    success: true,
    total,
    page: Number(page),
    count: result.length,
    data: result,
  });
};

// READ ONE: GET /api/products/:id
const getProductById = (req, res) => {
  const product = products.find((p) => p.id === Number(req.params.id));

  if (!product) {
    return res.status(404).json({ success: false, message: 'Product not found' });
  }

  res.json({ success: true, data: product });
};

// UPDATE (full): PUT /api/products/:id
const replaceProduct = (req, res) => {
  const index = products.findIndex((p) => p.id === Number(req.params.id));

  if (index === -1) {
    return res.status(404).json({ success: false, message: 'Product not found' });
  }

  const { name, price, category } = req.body;

  if (!name || price === undefined || !category) {
    return res.status(400).json({
      success: false,
      message: 'PUT requires name, price and category',
    });
  }

  products[index] = { id: products[index].id, name, price, category };
  res.json({ success: true, data: products[index] });
};

// UPDATE (partial): PATCH /api/products/:id
const updateProduct = (req, res) => {
  const product = products.find((p) => p.id === Number(req.params.id));

  if (!product) {
    return res.status(404).json({ success: false, message: 'Product not found' });
  }

  const { name, price, category } = req.body;
  if (name !== undefined) product.name = name;
  if (price !== undefined) product.price = price;
  if (category !== undefined) product.category = category;

  res.json({ success: true, data: product });
};

// DELETE: DELETE /api/products/:id
const deleteProduct = (req, res) => {
  const id = Number(req.params.id);
  const exists = products.some((p) => p.id === id);

  if (!exists) {
    return res.status(404).json({ success: false, message: 'Product not found' });
  }

  products = products.filter((p) => p.id !== id);
  res.sendStatus(204);
};

module.exports = {
  createProduct,
  getProducts,
  getProductById,
  replaceProduct,
  updateProduct,
  deleteProduct,
};
```

### `routes/productRoutes.js`

```js
const express = require('express');
const router = express.Router();

const {
  createProduct,
  getProducts,
  getProductById,
  replaceProduct,
  updateProduct,
  deleteProduct,
} = require('../controllers/productController');

router.route('/')
  .get(getProducts)
  .post(createProduct);

router.route('/:id')
  .get(getProductById)
  .put(replaceProduct)

```

### `middleware/errorHandler.js`

```js
const notFound = (req, res, next) => {
  const err = new Error(`Route not found: ${req.method} ${req.originalUrl}`);
  err.status = 404;
  next(err);
};

const errorHandler = (err, req, res, next) => {
  // malformed JSON in the request body
  if (err.type === 'entity.parse.failed') {
    return res.status(400).json({ success: false, message: 'Invalid JSON body' });
  }

  const status = err.status || 500;

  res.status(status).json({
    success: false,
    message: err.message || 'Internal Server Error',
    ...(process.env.NODE_ENV === 'development' && { stack: err.stack }),
  });
};

module.exports = { notFound, errorHandler };
```

### `index.js`

```js
require('dotenv').config();
const express = require('express');
const cors = require('cors');
const morgan = require('morgan');

const productRoutes = require('./routes/productRoutes');
const { notFound, errorHandler } = require('./middleware/errorHandler');

const app = express();
const PORT = process.env.PORT || 3000;

// ---------- Global middleware ----------
app.use(cors());
app.use(morgan('dev'));
app.use(express.json());
app.use(express.urlencoded({ extended: true }));

// ---------- Routes ----------
app.get('/', (req, res) => {
  res.json({ message: 'Products API is running' });
});

app.use('/api/products', productRoutes);

// ---------- Error handling (last) ----------
app.use(notFound);
app.use(errorHandler);

app.listen(PORT, () => {
  console.log(`Server running at http://localhost:${PORT}`);
});
```

### Why split into routes and controllers?

|Layer|Responsibility|
|---|---|
|**Routes**|Map URL + method to a controller function|
|**Controllers**|Contain the logic for each operation|
|**Middleware**|Cross-cutting concerns: logging, auth, validation, errors|
|**Models** (later)|Talk to the database|

This is the **MVC-style** structure you'll use with MongoDB and Mongoose.

## 5. Putting It All Together

How a request flows through the final app:

```
POST /api/products   (Content-Type: application/json)
        |
        v
  cors()                  allow the origin
        |
        v
  morgan('dev')           log "POST /api/products 201"
        |
        v
  express.json()          fills req.body
        |
        v
  router -> POST /        matches productRoutes
        |
        v
  createProduct()         validate, save, res.status(201).json(...)
        |
        v
  Response sent to the client

  (If nothing matched)  -> notFound -> errorHandler -> JSON error
```

### Adding a custom validation middleware

Move validation out of the controller to keep it clean:

```js
// middleware/validateProduct.js
const validateProduct = (req, res, next) => {
  const { name, price } = req.body;
  const errors = [];

  if (!name || typeof name !== 'string' || name.trim().length < 2) {
    errors.push('Name must be at least 2 characters');
  }
  if (typeof price !== 'number' || price < 0) {
    errors.push('Price must be a non-negative number');
  }

  if (errors.length) {
    return res.status(400).json({ success: false, errors });
  }

  next();
};

module.exports = validateProduct;
```

```js
// routes/productRoutes.js
const validateProduct = require('../middleware/validateProduct');

router.post('/', validateProduct, createProduct);
router.put('/:id', validateProduct, replaceProduct);
```

|Operation|Success|Failure|
|---|---|---|

|Read all|`200`||

### Common mistakes

|Mistake|Fix|
|---|---|
|`req.body` is `undefined`|Add `express.json()` **before** routes|
|Forgetting `next()`|Request hangs; call `next()` or send a response|
|Calling `next()` **and** sending a response|Use `return res...` or `return next()`|
|Error handler not working|It needs exactly 4 params and must be defined **last**|
|404 handler placed before routes|Put it after all routes|
|Verbs in URLs (`/getUsers`)|Use nouns + HTTP methods (`GET /users`)|
|Always returning `200`|Use proper codes: `201`, `204`, `400`, `404`|
|Comparing `req.params.id` to a number directly|`Number(req.params.id)`|
|Mutating the original array when sorting|Copy first: `[...products]`|
|No size limit on JSON|`express.json({ limit: '10kb' })`|
|Leaking error stack traces in production|Only include `stack` in development|

### Summary

- **Middleware** are functions `(req, res, next)` that run in order; they can modify the request, end it, or pass it on. Error middleware has four parameters and goes last.
- **Body parsing** (`express.json()`, `express.urlencoded()`) fills `req.body`; add it before your routes.
- **REST** designs APIs around resources: nouns in URLs, HTTP methods as verbs, proper status codes, JSON responses.
- **CRUD** maps to `POST`, `GET`, `PUT/PATCH`, `DELETE`; organise code into routes, controllers, and middleware.
