
## 1. Validation

### Why validate?

**Never trust data from the client.** Users (or attackers) can send missing fields, wrong types, huge strings, or malicious input. Validation checks the data **before** it reaches your logic or database.

|Without validation|With validation|
|---|---|
|Crashes on `undefined`|Clean `400` error|
|Garbage saved in the database|Only valid data saved|
|Security holes (injection, abuse)|Safer API|

### Manual validation

```js
app.post('/api/register', (req, res) => {
  const { name, email, password } = req.body;
  const errors = [];

  if (!name || name.trim().length < 2) errors.push('Name must be at least 2 characters');
  if (!email || !/^\S+@\S+\.\S+$/.test(email)) errors.push('Valid email is required');
  if (!password || password.length < 6) errors.push('Password must be at least 6 characters');

  if (errors.length) {
    return res.status(400).json({ success: false, errors });
  }

  res.status(201).json({ success: true });
});
```

This works but becomes repetitive. Use a validation library.

### Option A: express-validator

```bash
npm install express-validator
```

```js
const { body, validationResult } = require('express-validator');

const registerRules = [
  body('name')
    .trim()
    .notEmpty().withMessage('Name is required')
    .isLength({ min: 2 }).withMessage('Name must be at least 2 characters'),

  body('email')
    .trim()
    .isEmail().withMessage('Valid email is required')
    .normalizeEmail(),

  body('password')
    .isLength({ min: 6 }).withMessage('Password must be at least 6 characters')
    .matches(/\d/).withMessage('Password must contain a number'),
];

// reusable middleware that checks the result
const validate = (req, res, next) => {
  const result = validationResult(req);

  if (!result.isEmpty()) {
    return res.status(400).json({
      success: false,
      errors: result.array().map((e) => ({ field: e.path, message: e.msg })),
    });
  }

  next();
};

app.post('/api/register', registerRules, validate, (req, res) => {
  res.status(201).json({ success: true, message: 'Valid data!' });
});
```

Common validators:

|Validator|Checks|
|---|---|
|`.notEmpty()`|Not empty|
|`.isEmail()`|Valid email|
|`.isLength({ min, max })`|String length|
|`.isInt({ min, max })`|Integer in range|
|`.isNumeric()`|Numbers only|
|`.isIn(['a','b'])`|One of the allowed values|
|`.isMongoId()`|Valid MongoDB ObjectId|
|`.matches(regex)`|Matches a pattern|
|`.trim()` / `.escape()`|Sanitizers: clean the input|
|`.custom(fn)`|Your own rule|

Validating params and query:

```js
const { param, query } = require('express-validator');

router.get('/:id', param('id').isInt().withMessage('ID must be a number'), validate, getOne);
router.get('/', query('page').optional().isInt({ min: 1 }), validate, getAll);
```

Custom rule (confirm password):

```js
body('confirmPassword').custom((value, { req }) => {
  if (value !== req.body.password) {
    throw new Error('Passwords do not match');
  }
  return true;
}),
```

### Option B: Joi

```bash
npm install joi
```

```js
const Joi = require('joi');

const registerSchema = Joi.object({
  name: Joi.string().min(2).max(50).required(),
  email: Joi.string().email().required(),
  password: Joi.string().min(6).required(),
  age: Joi.number().integer().min(13).optional(),
});

const validateBody = (schema) => (req, res, next) => {
  const { error, value } = schema.validate(req.body, {
    abortEarly: false,     // return all errors, not just the first
    stripUnknown: true,    // remove fields not in the schema
  });

  if (error) {
    return res.status(400).json({
      success: false,
      errors: error.details.map((d) => d.message),
    });
  }

  req.body = value;        // use the cleaned data
  next();
};

app.post('/api/register', validateBody(registerSchema), registerUser);
```

### express-validator vs Joi

||express-validator|Joi|
|---|---|---|
|Style|Chained middleware per field|Schema object|
|Sanitizing|Built in|Limited|
|Reusability|Rules arrays|Schemas|
|Popular with|Express apps|APIs, any Node code|

> Mongoose also has built-in schema validation (covered in the MongoDB note). Validate in **both** places for defence in depth.

## 2. Error Handling Middleware

### Goal

Handle every error in **one central place** instead of repeating `try/catch` + `res.status(500)` in every route.

### Error middleware signature

Exactly **four** parameters, defined **after** all routes:

```js
app.use((err, req, res, next) => {
  res.status(err.status || 500).json({ message: err.message });
});
```

### Custom error class

```js
// utils/AppError.js
class AppError extends Error {
  constructor(message, statusCode) {
    super(message);
    this.statusCode = statusCode;
    this.isOperational = true;           // expected error (not a bug)
    Error.captureStackTrace(this, this.constructor);
  }
}

module.exports = AppError;
```

Use it anywhere:

```js
const AppError = require('../utils/AppError');

const getUser = async (req, res, next) => {
  const user = await User.findById(req.params.id);

  if (!user) {
    return next(new AppError('User not found', 404));
  }

  res.json({ success: true, data: user });
};
```

### asyncHandler (avoid try/catch everywhere)

```js
// utils/asyncHandler.js
const asyncHandler = (fn) => (req, res, next) =>
  Promise.resolve(fn(req, res, next)).catch(next);

module.exports = asyncHandler;
```

```js
const getUsers = asyncHandler(async (req, res) => {
  const users = await User.find();    // any thrown error goes to the error middleware
  res.json({ success: true, data: users });
});
```

> Express 5 handles rejected promises automatically, so `asyncHandler` is only needed on Express 4.

### Central error handler

```js
// middleware/errorHandler.js
const AppError = require('../utils/AppError');

const notFound = (req, res, next) => {
  next(new AppError(`Route not found: ${req.method} ${req.originalUrl}`, 404));
};

const errorHandler = (err, req, res, next) => {
  let statusCode = err.statusCode || 500;
  let message = err.message || 'Internal Server Error';

  // Mongoose: invalid ObjectId
  if (err.name === 'CastError') {
    statusCode = 400;
    message = `Invalid ${err.path}: ${err.value}`;
  }

  // Mongoose: duplicate key (e.g. unique email)
  if (err.code === 11000) {
    statusCode = 409;
    const field = Object.keys(err.keyValue)[0];
    message = `${field} already exists`;
  }

  // Mongoose: validation error
  if (err.name === 'ValidationError') {
    statusCode = 400;
    message = Object.values(err.errors).map((e) => e.message).join(', ');
  }

  // JWT errors
  if (err.name === 'JsonWebTokenError') {
    statusCode = 401;
    message = 'Invalid token';
  }
  if (err.name === 'TokenExpiredError') {
    statusCode = 401;
    message = 'Token expired, please log in again';
  }

  // Malformed JSON body
  if (err.type === 'entity.parse.failed') {
    statusCode = 400;
    message = 'Invalid JSON body';
  }

  res.status(statusCode).json({
    success: false,
    message,
    ...(process.env.NODE_ENV === 'development' && { stack: err.stack }),
  });
};

module.exports = { notFound, errorHandler };
```

### Register in the right order

```js
app.use(express.json());

app.use('/api/auth', authRoutes);
app.use('/api/users', userRoutes);

app.use(notFound);        // 1. catches unknown routes
app.use(errorHandler);    // 2. catches everything else (LAST)
```

### Error types cheat sheet

|Error|Source|Status|
|---|---|---|
|`ValidationError`|Mongoose schema rules|400|
|`CastError`|Invalid ObjectId|400|
|`code 11000`|Duplicate unique field|409|
|`JsonWebTokenError`|Bad/forged token|401|
|`TokenExpiredError`|Expired token|401|
|`entity.parse.failed`|Broken JSON body|400|
|`AppError`|Your own errors|You choose|
|Anything else|Unexpected bug|500|

### Catch crashes outside Express

```js
process.on('unhandledRejection', (err) => {
  console.error('Unhandled rejection:', err.message);
  server.close(() => process.exit(1));
});

process.on('uncaughtException', (err) => {
  console.error('Uncaught exception:', err.message);
  process.exit(1);
});
```

## 3. bcrypt (Password Hashing)

### The rule

**Never store plain-text passwords.** If your database leaks, every user's password is exposed. Store a **hash** instead.

||Encryption|Hashing|
|---|---|---|
|Reversible?|Yes (with a key)|**No**, one-way|
|Use for|Data you must read back|Passwords|

### What is bcrypt?

**bcrypt** is a password-hashing algorithm designed to be **slow** (to resist brute force) and to add a random **salt** automatically.

- **Salt**: random data added to each password so identical passwords produce different hashes.
- **Salt rounds (cost factor)**: how much work the hash takes. Each +1 doubles the time. **10 to 12** is typical.

```
"mypassword"  --bcrypt-->  $2b$10$N9qo8uLOickgx2ZMRZoMyeIjZAgcfl7p92ldGxad68LJZdL17lhWy
```

### Install

```bash
npm install bcrypt
# or bcryptjs (pure JavaScript, no native build step)
npm install bcryptjs
```

### Hashing a password

```js
const bcrypt = require('bcrypt');

const hashPassword = async (plain) => {
  const hash = await bcrypt.hash(plain, 10);   // 10 salt rounds
  return hash;
};

hashPassword('mypassword').then(console.log);
// $2b$10$...
```

### Comparing a password

```js
const isMatch = await bcrypt.compare('mypassword', storedHash);
console.log(isMatch);   // true or false
```

> You can never "decrypt" a hash. You hash the login attempt and **compare**.

### Registration flow

```js
const register = asyncHandler(async (req, res) => {
  const { name, email, password } = req.body;

  const exists = await User.findOne({ email });
  if (exists) throw new AppError('Email already registered', 409);

  const hashedPassword = await bcrypt.hash(password, 10);

  const user = await User.create({ name, email, password: hashedPassword });

  res.status(201).json({
    success: true,
    data: { id: user._id, name: user.name, email: user.email },   // never return the password
  });
});
```

### Login flow

```js
const login = asyncHandler(async (req, res) => {
  const { email, password } = req.body;

  const user = await User.findOne({ email });

  // same message for both cases: don't reveal which one failed
  if (!user || !(await bcrypt.compare(password, user.password))) {
    throw new AppError('Invalid email or password', 401);
  }

  // ... create and send a JWT (next section)
});
```

### Good practices

|Do|Don't|
|---|---|
|Hash with 10 to 12 rounds|Store plain or MD5/SHA1 passwords|
|Use `await bcrypt.hash()` (async)|Use `hashSync` in a server (blocks the event loop)|
|Return a generic "Invalid email or password"|Say "email not found" (helps attackers)|
|Exclude the password from responses|Send the user document with the hash|
|Enforce a minimum password length|Allow 1-character passwords|

## 4. JWT Authentication

### What is JWT?

**JSON Web Token** is a compact, signed token that proves who a user is. After login, the server issues a token; the client sends it with every later request.

### Session vs JWT

||Session (cookie)|JWT|
|---|---|---|
|State stored|**On the server**|**In the token** (stateless)|
|Scaling|Needs shared session store|Easy to scale|
|Best for|Traditional server-rendered apps|REST APIs, SPAs, mobile apps|

### Structure of a JWT

Three Base64 parts separated by dots:

```
eyJhbGciOiJIUzI1NiJ9 . eyJpZCI6IjEyMyIsImlhdCI6MTcwMDAwMDAwMH0 . Sflk3k...
      HEADER                         PAYLOAD                         SIGNATURE
```

|Part|Contains|
|---|---|
|**Header**|Algorithm and token type: `{ "alg": "HS256", "typ": "JWT" }`|
|**Payload**|Claims: `{ "id": "123", "role": "user", "iat": ..., "exp": ... }`|
|**Signature**|Hash of header + payload using your **secret**, proves it wasn't tampered with|

> The payload is **encoded, not encrypted**. Anyone can read it (try https://jwt.io). Never put passwords or secrets inside.

### Authentication flow

```
1. Client  --- POST /login (email, password) --->  Server
2. Server  verifies password with bcrypt
3. Server  --- JWT token --->  Client   (stores it)
4. Client  --- GET /profile + "Authorization: Bearer <token>" --->  Server
5. Server  verifies token signature + expiry, identifies the user
6. Server  --- protected data --->  Client
```

### Install

```bash
npm install jsonwebtoken
```

`.env`:

```env
JWT_SECRET=use_a_long_random_string_at_least_32_chars
JWT_EXPIRES_IN=7d
```

Generate a strong secret:

```bash
node -e "console.log(require('crypto').randomBytes(64).toString('hex'))"
```

### Creating a token (`jwt.sign`)

```js
const jwt = require('jsonwebtoken');

const generateToken = (userId) => {
  return jwt.sign(
    { id: userId },                          // payload
    process.env.JWT_SECRET,                  // secret
    { expiresIn: process.env.JWT_EXPIRES_IN || '7d' }   // options
  );
};
```

### Verifying a token (`jwt.verify`)

```js
try {
  const decoded = jwt.verify(token, process.env.JWT_SECRET);
  console.log(decoded);   // { id: '123', iat: 1700000000, exp: 1700604800 }
} catch (err) {
  console.log(err.name);  // 'JsonWebTokenError' or 'TokenExpiredError'
}
```

### Complete login with JWT

```js
const login = asyncHandler(async (req, res) => {
  const { email, password } = req.body;

  const user = await User.findOne({ email });

  if (!user || !(await bcrypt.compare(password, user.password))) {
    throw new AppError('Invalid email or password', 401);
  }

  const token = generateToken(user._id);

  res.json({
    success: true,
    token,
    user: { id: user._id, name: user.name, email: user.email },
  });
});
```

### How the client sends the token

In the `Authorization` header using the **Bearer** scheme:

```
Authorization: Bearer eyJhbGciOiJIUzI1NiJ9.eyJpZCI6IjEyMyJ9.Sflk3k...
```

```js
// fetch
fetch('/api/profile', {
  headers: { Authorization: `Bearer ${token}` },
});

// axios
axios.get('/api/profile', {
  headers: { Authorization: `Bearer ${token}` },
});
```

### Common `expiresIn` values

|Value|Meaning|
|---|---|
|`'15m'`|15 minutes|
|`'1h'`|1 hour|
|`'7d'`|7 days|
|`3600`|3600 seconds|

### Access token + refresh token (concept)

- **Access token**: short life (15 min), sent with every request.
- **Refresh token**: long life (7 to 30 days), used only to get a new access token.

This limits the damage if an access token is stolen.

### Where should the client store the JWT?

|Storage|Pros|Cons|
|---|---|---|
|`localStorage`|Simple|Readable by JavaScript, vulnerable to **XSS**|
|**httpOnly cookie**|JavaScript can't read it, safer against XSS|Needs CORS/CSRF care|

Setting an httpOnly cookie from Express:

```js
res.cookie('token', token, {
  httpOnly: true,
  secure: process.env.NODE_ENV === 'production',   // HTTPS only in production
  sameSite: 'strict',
  maxAge: 7 * 24 * 60 * 60 * 1000,                 // 7 days
});
```

(This is revisited in the React and MERN notes.)

### JWT security rules

- Keep `JWT_SECRET` in `.env`, long and random, never in Git.
- Always set an expiry.
- Never store sensitive data in the payload.
- Use HTTPS in production.
- Verify the token on **every** protected request.

## 5. Protected Routes

### Idea

A **protected route** can only be accessed by authenticated users. An **auth middleware** checks the token before the route handler runs.

```
Request --> authMiddleware --> valid token? --yes--> route handler
                                   |
                                   no --> 401 Unauthorized
```

### User model (Mongoose, preview)

```js
// models/User.js
const mongoose = require('mongoose');

const userSchema = new mongoose.Schema(
  {
    name: { type: String, required: true, trim: true },
    email: { type: String, required: true, unique: true, lowercase: true },
    password: { type: String, required: true, minlength: 6, select: false }, // hidden by default
    role: { type: String, enum: ['user', 'admin'], default: 'user' },
  },
  { timestamps: true }
);

module.exports = mongoose.model('User', userSchema);
```

> `select: false` keeps the password out of query results. When you need it (login), use `.select('+password')`.

### Auth middleware (`protect`)

```js
// middleware/auth.js
const jwt = require('jsonwebtoken');
const User = require('../models/User');
const AppError = require('../utils/AppError');
const asyncHandler = require('../utils/asyncHandler');

const protect = asyncHandler(async (req, res, next) => {
  let token;

  // 1. get the token from the header (or a cookie)
  if (req.headers.authorization?.startsWith('Bearer ')) {
    token = req.headers.authorization.split(' ')[1];
  } else if (req.cookies?.token) {
    token = req.cookies.token;
  }

  if (!token) {
    throw new AppError('Not authorized, no token provided', 401);
  }

  // 2. verify it (throws if invalid or expired)
  const decoded = jwt.verify(token, process.env.JWT_SECRET);

  // 3. make sure the user still exists
  const user = await User.findById(decoded.id);
  if (!user) {
    throw new AppError('The user for this token no longer exists', 401);
  }

  // 4. attach the user to the request
  req.user = user;
  next();
});

module.exports = { protect };
```

### Role-based access (`restrictTo`)

```js
const restrictTo = (...roles) => (req, res, next) => {
  if (!roles.includes(req.user.role)) {
    return next(new AppError('You do not have permission to do this', 403));
  }
  next();
};

module.exports = { protect, restrictTo };
```

### Using the middleware

```js
const { protect, restrictTo } = require('../middleware/auth');

// public
router.post('/register', registerRules, validate, register);
router.post('/login', loginRules, validate, login);

// any logged-in user
router.get('/me', protect, getMe);

// admin only
router.get('/users', protect, restrictTo('admin'), getAllUsers);
router.delete('/users/:id', protect, restrictTo('admin'), deleteUser);

// protect an entire router
router.use(protect);
```

### Controller using `req.user`

```js
const getMe = asyncHandler(async (req, res) => {
  res.json({ success: true, data: req.user });   // set by protect
});
```

### Ownership check (users edit only their own data)

```js
const updatePost = asyncHandler(async (req, res) => {
  const post = await Post.findById(req.params.id);
  if (!post) throw new AppError('Post not found', 404);

  if (post.author.toString() !== req.user.id && req.user.role !== 'admin') {
    throw new AppError('You can only edit your own posts', 403);
  }

  Object.assign(post, req.body);
  await post.save();
  res.json({ success: true, data: post });
});
```

### 401 vs 403

|Code|Meaning|Example|
|---|---|---|
|**401 Unauthorized**|Not authenticated: no/invalid token|Missing or expired token|
|**403 Forbidden**|Authenticated but not allowed|A normal user calling an admin route|

### `controllers/authController.js`

```js
const bcrypt = require('bcrypt');
const jwt = require('jsonwebtoken');
const User = require('../models/User');
const AppError = require('../utils/AppError');
const asyncHandler = require('../utils/asyncHandler');

const signToken = (id) =>
  jwt.sign({ id }, process.env.JWT_SECRET, { expiresIn: process.env.JWT_EXPIRES_IN });

// POST /api/auth/register
exports.register = asyncHandler(async (req, res) => {
  const { name, email, password } = req.body;

  if (await User.findOne({ email })) {
    throw new AppError('Email already registered', 409);
  }

  const hashed = await bcrypt.hash(password, 10);
  const user = await User.create({ name, email, password: hashed });

  res.status(201).json({
    success: true,
    token: signToken(user._id),
    user: { id: user._id, name: user.name, email: user.email, role: user.role },
  });
});

// POST /api/auth/login
exports.login = asyncHandler(async (req, res) => {
  const { email, password } = req.body;

  const user = await User.findOne({ email }).select('+password');

  if (!user || !(await bcrypt.compare(password, user.password))) {
    throw new AppError('Invalid email or password', 401);
  }

  res.json({
    success: true,
    token: signToken(user._id),
    user: { id: user._id, name: user.name, email: user.email, role: user.role },
  });
});

// GET /api/auth/me   (protected)
exports.getMe = asyncHandler(async (req, res) => {
  res.json({ success: true, user: req.user });
});
```

### Request flow for a protected route

```
GET /api/auth/me   (Authorization: Bearer <token>)
      |
      v
  cors -> express.json -> router
      |
      v
  protect:  get token -> jwt.verify -> find user -> req.user = user -> next()
      |
      v
  getMe:    res.json({ user: req.user })

  Any error thrown along the way -> errorHandler -> JSON error response
```

## 7. Quick Reference

### Cheat sheet

```js
// Hash + compare
const hash = await bcrypt.hash(password, 10);
const ok = await bcrypt.compare(password, hash);

// Sign + verify
const token = jwt.sign({ id }, process.env.JWT_SECRET, { expiresIn: '7d' });
const decoded = jwt.verify(token, process.env.JWT_SECRET);

// Header format
// Authorization: Bearer <token>

// Protect routes
router.get('/me', protect, getMe);
router.delete('/:id', protect, restrictTo('admin'), remove);

// Throw errors anywhere
throw new AppError('Not found', 404);

// Error handler: last, with 4 params
app.use((err, req, res, next) => { ... });
```

### Status codes for auth

|Situation|Code|
|---|---|
|Registered successfully|`201`|
|Validation failed|`400`|
|Wrong email/password, missing/invalid token|`401`|
|Logged in but lacks permission|`403`|
|Email already exists|`409`|

### Common mistakes

|Mistake|Fix|
|---|---|
|Storing plain-text passwords|Always `bcrypt.hash()` before saving|
|Using `hashSync` / `compareSync` on a server|Use the async versions|
|Returning the password hash in responses|`select: false` and build the response manually|
|Telling users "email not found" on login|Use one generic message|
|Hardcoding `JWT_SECRET`|Put it in `.env` (long, random)|
|No token expiry|Always set `expiresIn`|
|Putting sensitive data in the JWT payload|Only store the user id (and role if needed)|
|Forgetting `Bearer` prefix when splitting|`authorization.split(' ')[1]`|
|Error handler defined before routes|Define it **last**|
|Missing `return` before `res.status().json()`|Add `return` or use `throw`|
|Validating only on the frontend|Always validate on the server too|
|Mixing up 401 and 403|401 = who are you? 403 = you can't do this|
|Storing tokens in `localStorage` for high-security apps|Prefer httpOnly cookies|

### Summary

- **Validation** (express-validator / Joi) rejects bad input with `400` before it reaches your logic.
- **Error handling middleware** centralises errors with `AppError`, `asyncHandler`, and one final `(err, req, res, next)` handler.
- **bcrypt** hashes passwords one-way with a salt; use `bcrypt.compare()` at login.
- **JWT** is a signed token issued at login and sent as `Authorization: Bearer <token>`; verify it with `jwt.verify()`.
- **Protected routes** use a `protect` middleware to authenticate and `restrictTo` to authorise by role.
