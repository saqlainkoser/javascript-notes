## 1. NPM (Node Package Manager)

### What is it?

**NPM** is the default package manager for Node.js. It does three things:

1. **Registry**: a huge online library of open-source packages (https://www.npmjs.com).
2. **CLI tool**: the `npm` command you run in the terminal.
3. **Dependency manager**: installs, updates, and removes packages for your project.

It is installed automatically with Node.js.

```bash
node -v     # Node version
npm -v      # NPM version
```

### Why use packages?

Instead of writing everything from scratch, you reuse tested code: `express` for servers, `mongoose` for MongoDB, `bcrypt` for hashing, `dotenv` for env files, and so on.

### Core commands

|Command|Purpose|
|---|---|
|`npm init`|Create `package.json` interactively|
|`npm init -y`|Create `package.json` with defaults|
|`npm install <pkg>`|Install a package (short: `npm i <pkg>`)|
|`npm install`|Install everything listed in `package.json`|
|`npm install <pkg> --save-dev`|Install as a dev dependency (short: `-D`)|
|`npm install -g <pkg>`|Install globally|
|`npm uninstall <pkg>`|Remove a package|
|`npm update`|Update packages within allowed version ranges|
|`npm list`|Show installed packages|
|`npm list --depth=0`|Show only top-level packages|
|`npm outdated`|Show packages with newer versions|
|`npm run <script>`|Run a script from `package.json`|
|`npm audit`|Check for security vulnerabilities|
|`npm audit fix`|Auto-fix vulnerabilities where possible|

### Installing packages

```bash
# Local install (project only)
npm install express

# Multiple at once
npm install express mongoose dotenv

# Specific version
npm install express@4.18.2

# Dev dependency (only needed during development)
npm install nodemon --save-dev

# Global install (available everywhere in the terminal)
npm install -g nodemon
```

### Using an installed package

```js
const express = require('express');   // CommonJS
// or
import express from 'express';        // ES Modules

const app = express();
```

### What gets created after install?

```
my-project/
├── node_modules/        <- downloaded packages (never commit this)
├── package.json         <- project info + dependency list
├── package-lock.json    <- exact version snapshot (commit this)
└── index.js
```

|Item|Description|
|---|---|
|`node_modules/`|Contains all installed packages and their dependencies. It can be huge.|
|`package-lock.json`|Locks the **exact** versions installed, so everyone gets identical results.|

### `.gitignore`

Never push `node_modules` or secret files to GitHub.

```
node_modules/
.env
```

Anyone can recreate `node_modules` by running:

```bash
npm install
```

### Local vs Global packages

||Local|Global|
|---|---|---|
|Location|`./node_modules`|System-wide folder|
|Used by|Only that project|Any terminal|
|Typical use|`express`, `mongoose`|CLI tools like `nodemon`, `typescript`|
|Command|`npm i pkg`|`npm i -g pkg`|

### npx

`npx` runs a package **without installing it permanently**.

```bash
npx create-vite@latest my-app
npx nodemon index.js
```

### Semantic Versioning (SemVer)

A version looks like `MAJOR.MINOR.PATCH`, for example `4.18.2`.

|Part|Changes when...|
|---|---|
|`MAJOR` (4)|Breaking changes|
|`MINOR` (18)|New features, backward compatible|
|`PATCH` (2)|Bug fixes|

Symbols in `package.json`:

|Symbol|Example|Meaning|
|---|---|---|
|`^`|`^4.18.2`|Allow minor + patch updates (`4.x.x`)|
|`~`|`~4.18.2`|Allow only patch updates (`4.18.x`)|
|none|`4.18.2`|Exact version only|
|`*`|`*`|Any version (avoid)|

## 2. package.json

### What is it?

`package.json` is the **manifest file** of a Node.js project. It stores metadata, dependencies, and scripts.

### Creating it

```bash
npm init -y
```

### Example

```json
{
  "name": "my-node-app",
  "version": "1.0.0",
  "description": "A simple Node.js server",
  "main": "index.js",
  "type": "commonjs",
  "scripts": {
    "start": "node index.js",
    "dev": "nodemon index.js",
    "test": "echo \"Error: no test specified\" && exit 1"
  },
  "keywords": ["node", "express"],
  "author": "Your Name",
  "license": "ISC",
  "dependencies": {
    "dotenv": "^16.4.5",
    "express": "^4.19.2"
  },
  "devDependencies": {
    "nodemon": "^3.1.0"
  }
}
```

### Important fields

|Field|Description|
|---|---|
|`name`|Project name (lowercase, no spaces)|
|`version`|Current project version (SemVer)|
|`description`|Short summary|
|`main`|Entry point file (`index.js`, `app.js`, `server.js`)|
|`type`|`"commonjs"` (default) or `"module"` for ES Modules|
|`scripts`|Custom terminal commands|
|`dependencies`|Packages required to **run** the app|
|`devDependencies`|Packages required only for **development**|
|`author` / `license`|Ownership info|
|`engines`|Required Node.js version|

### dependencies vs devDependencies

```bash
npm install express             # goes in "dependencies"
npm install nodemon -D          # goes in "devDependencies"
```

||dependencies|devDependencies|
|---|---|---|
|Needed in production?|Yes|No|
|Examples|`express`, `mongoose`, `bcrypt`, `jsonwebtoken`|`nodemon`, `jest`, `eslint`, `prettier`|

In production, install without dev packages:

```bash
npm install --omit=dev
```

### Scripts

Scripts are shortcuts for terminal commands.

```json
"scripts": {
  "start": "node index.js",
  "dev": "nodemon index.js",
  "lint": "eslint .",
  "build": "echo Building..."
}
```

Run them:

```bash
npm start            # "start" and "test" don't need "run"
npm run dev          # all other scripts need "run"
npm run lint
```

### Using ES Modules (`import` / `export`)

Add `"type": "module"` to `package.json`:

```json
{
  "type": "module"
}
```

Now you can write:

```js
import http from 'http';
import express from 'express';

export const add = (a, b) => a + b;
```

> **Note:** With `"type": "module"`, `require()` and `__dirname` are not available by default.

### package.json vs package-lock.json

||package.json|package-lock.json|
|---|---|---|
|Written by|You (and npm)|npm automatically|
|Versions|Ranges (`^4.18.2`)|Exact (`4.18.2`)|
|Purpose|Describe the project|Guarantee identical installs|
|Commit to Git?|Yes|Yes|

## 3. Nodemon

### The problem

By default, Node does **not** reload your server when you change code. You must stop (`Ctrl + C`) and restart manually every time.

```bash
node index.js     # change code -> must restart yourself
```

### The solution

**Nodemon** watches your files and **automatically restarts** the server whenever you save a change.

### Installation

```bash
# Recommended: as a dev dependency
npm install nodemon --save-dev

# Or globally
npm install -g nodemon
```

### Usage

**Option 1: Run directly**

```bash
npx nodemon index.js
```

**Option 2: Add a script (recommended)**

```json
"scripts": {
  "start": "node index.js",
  "dev": "nodemon index.js"
}
```

```bash
npm run dev
```

### What you will see

```
[nodemon] 3.1.0
[nodemon] to restart at any time, enter `rs`
[nodemon] watching path(s): *.*
[nodemon] watching extensions: js,mjs,cjs,json
[nodemon] starting `node index.js`
Server running on port 3000
[nodemon] restarting due to changes...
[nodemon] starting `node index.js`
Server running on port 3000
```

### Useful tips

|Action|How|
|---|---|
|Manually restart|Type `rs` and press Enter|
|Stop|`Ctrl + C`|
|Watch specific folder|`nodemon --watch src index.js`|
|Watch extra extensions|`nodemon -e js,json,html index.js`|
|Ignore files|`nodemon --ignore logs/ index.js`|

### Config file: `nodemon.json`

```json
{
  "watch": ["src"],
  "ext": "js,json",
  "ignore": ["node_modules", "logs"],
  "exec": "node index.js"
}
```

Then simply run `nodemon`.

### Node's built-in watch mode (alternative)

Node 18.11+ includes a built-in watcher:

```bash
node --watch index.js
```

```json
"scripts": {
  "dev": "node --watch index.js"
}
```

### Development vs production

||`npm run dev`|`npm start`|
|---|---|---|
|Tool|nodemon|node|
|Auto-restart|Yes|No|
|Use|Local development|Production|

> **Never** use nodemon in production. Use `node` (or a process manager like **PM2**).

## 4. Environment Variables

### What are they?

**Environment variables** are key-value settings stored **outside your code**. They hold values that change between machines or environments (development, testing, production).

### Why use them?

|Reason|Example|
|---|---|
|**Security**|Keep passwords, API keys, and JWT secrets out of your code and Git|
|**Flexibility**|Use a different database/port in dev and production|
|**Clean code**|No hardcoded values scattered around|

### Bad vs good

```js
// BAD: secrets hardcoded and pushed to GitHub
const dbUrl = 'mongodb+srv://admin:MyPassword123@cluster.mongodb.net/mydb';
const jwtSecret = 'supersecret';

// GOOD: read from environment
const dbUrl = process.env.MONGO_URI;
const jwtSecret = process.env.JWT_SECRET;
```

### `process.env`

Node exposes all environment variables through the global `process.env` object. **Values are always strings.**

```js
console.log(process.env.PATH);
console.log(process.env.NODE_ENV);   // undefined unless you set it
```

### Setting variables from the terminal

**macOS / Linux**

```bash
PORT=5000 node index.js
```

**Windows (PowerShell)**

```powershell
$env:PORT=5000; node index.js
```

**Windows (CMD)**

```cmd
set PORT=5000 && node index.js
```

```js
// index.js
console.log(process.env.PORT);   // "5000"
```

### Using a `.env` file with dotenv

Typing variables in the terminal each time is tedious. The **dotenv** package loads them from a `.env` file.

**Step 1: Install**

```bash
npm install dotenv
```

**Step 2: Create `.env` in the project root**

```env
PORT=3000
NODE_ENV=development
MONGO_URI=mongodb://localhost:27017/mydb
JWT_SECRET=my_super_secret_key
API_KEY=abc123xyz
```

> Rules: no spaces around `=`, no quotes needed (unless the value has spaces), and no semicolons.

**Step 3: Load it at the top of your entry file**

```js
// CommonJS
require('dotenv').config();

// ES Modules
import 'dotenv/config';
```

**Step 4: Use the values**

```js
const http = require('http');
require('dotenv').config();

const PORT = process.env.PORT || 3000;

http.createServer((req, res) => {
  res.end(`Running in ${process.env.NODE_ENV} mode`);
}).listen(PORT, () => {
  console.log(`Server running on port ${PORT}`);
});
```

> `dotenv.config()` must run **before** you read `process.env` anywhere else.

### Native `.env` support (Node 20.6+)

No package required:

```bash
node --env-file=.env index.js
```

```json
"scripts": {
  "dev": "nodemon --env-file=.env index.js"
}
```

### Protect your secrets

**1. Add `.env` to `.gitignore`**

```
node_modules/
.env
```

**2. Provide a `.env.example` template** (safe to commit, no real values)

```env
PORT=3000
NODE_ENV=development
MONGO_URI=
JWT_SECRET=
API_KEY=
```

Teammates copy it to `.env` and fill in their own values.

### Converting types

Because everything is a string, convert when needed:

```js
const PORT = Number(process.env.PORT) || 3000;
const DEBUG = process.env.DEBUG === 'true';
const MAX_USERS = parseInt(process.env.MAX_USERS, 10);
```

### NODE_ENV

A common convention to tell the app which environment it runs in.

```js
if (process.env.NODE_ENV === 'production') {
  console.log('Production mode: logging disabled');
} else {
  console.log('Development mode: verbose logging on');
}
```

|Value|Meaning|
|---|---|
|`development`|Local coding|
|`test`|Running automated tests|
|`production`|Live server|

### Multiple environment files (optional)

```
.env                  <- shared defaults
.env.development
.env.production
```

```js
require('dotenv').config({
  path: `.env.${process.env.NODE_ENV || 'development'}`,
});
```

### Validating required variables

Fail early if something is missing:

```js
const required = ['MONGO_URI', 'JWT_SECRET'];

required.forEach((key) => {
  if (!process.env[key]) {
    console.error(`Missing environment variable: ${key}`);
    process.exit(1);
  }
});
```

### Hosting platforms

On Render, Vercel, Railway, Heroku, and similar services you do **not** upload `.env`. You add variables in the platform's dashboard under **Environment Variables / Config Vars**, and `process.env` reads them automatically.

## 5. Putting It All Together

### Project structure

```
my-app/
├── node_modules/
├── .env
├── .env.example
├── .gitignore
├── package.json
├── package-lock.json
└── index.js
```

### Setup commands

```bash
mkdir my-app && cd my-app
npm init -y
npm install express dotenv
npm install nodemon --save-dev
```

### `.env`

```env
PORT=4000
NODE_ENV=development
APP_NAME=My First App
```

### `.gitignore`

```
node_modules/
.env
```

### `package.json` (scripts section)

```json
"scripts": {
  "start": "node index.js",
  "dev": "nodemon index.js"
}
```

### `index.js`

```js
require('dotenv').config();
const express = require('express');

const app = express();
const PORT = process.env.PORT || 3000;

app.get('/', (req, res) => {
  res.json({
    app: process.env.APP_NAME,
    mode: process.env.NODE_ENV,
    message: 'Hello from Express!',
  });
});

app.listen(PORT, () => {
  console.log(`${process.env.APP_NAME} running on http://localhost:${PORT}`);
});
```

### Run

```bash
npm run dev
```

Output:

```
My First App running on http://localhost:4000
```

Change any line in `index.js`, save, and nodemon restarts the server automatically.

## 6. Quick Reference

### Cheat sheet

```bash
# Project setup
npm init -y
npm install <pkg>
npm install <pkg> -D
npm install
npm uninstall <pkg>

# Run
npm start
npm run dev
npx nodemon index.js

# Maintenance
npm outdated
npm update
npm audit
```

```js
// dotenv
require('dotenv').config();
const PORT = process.env.PORT || 3000;
```

### Common mistakes

|Mistake|Fix|
|---|---|
|Pushing `node_modules` to Git|Add it to `.gitignore`|
|Pushing `.env` to Git|Add it to `.gitignore`; rotate any leaked secret|
|Calling `dotenv.config()` too late|Put it at the very top of the entry file|
|Spaces around `=` in `.env`|Write `KEY=value`|
|Treating env values as numbers/booleans|Convert: `Number()`, `=== 'true'`|
|Using nodemon in production|Use `node index.js` or PM2|
|Deleting `package-lock.json`|Keep it and commit it|
|Installing dev tools as dependencies|Use `-D` / `--save-dev`|
|`npm run start` vs `npm start` confusion|Both work; `start` and `test` can skip `run`|
|Missing `"type": "module"` when using `import`|Add it to `package.json` or use `.mjs`|

### Summary

- **NPM** installs and manages packages and runs scripts.
- **package.json** describes your project, lists dependencies, and defines scripts.
- **Nodemon** restarts your server automatically while you develop.
- **Environment variables** keep secrets and settings out of your code. Use `.env` with **dotenv**, read them via `process.env`, and never commit them.
