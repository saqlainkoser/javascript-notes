# Node.js Modules, File System (fs) & Path Module

## 1. Modules in Node.js

A **module** is a reusable block of code whose content is isolated from the rest of the application — each file in Node.js is treated as its own module. Node supports two systems: **CommonJS** and **ES Modules**.

---

### A. CommonJS (CJS)

The original, default module system in Node.js.

**Exporting** (`math.js`):

```js
function add(a, b) {
  return a + b;
}
function subtract(a, b) {
  return a - b;
}

module.exports = { add, subtract };

// OR export a single thing
module.exports = add;

// OR export one at a time
exports.add = add;
exports.subtract = subtract;
```

**Importing** (`app.js`):

```js
const { add, subtract } = require('./math');
console.log(add(2, 3)); // 5

// Importing built-in / npm modules
const fs = require('fs');
const express = require('express');
```

**Key notes:**

- `require()` is **synchronous** — loads modules line by line as it runs.
- `module.exports` / `exports` are objects Node automatically provides to every file.
- Files use `.js` (or `.cjs` explicitly).
- ⚠️ Reassigning `exports = {...}` breaks the reference — always use `module.exports = {...}` or mutate `exports.x = ...`.
- Each file gets access to `__dirname`, `__filename`, `require`, `module`, `exports` automatically.

---

### B. ES Modules (ESM)

The standard JavaScript module syntax (same as browsers).

**Exporting** (`math.js`, with `"type": "module"` set):

```js
export function add(a, b) {
  return a + b;
}
export function subtract(a, b) {
  return a - b;
}

// Default export
export default function multiply(a, b) {
  return a * b;
}
```

**Importing** (`app.js`):

```js
import multiply, { add, subtract } from './math.js';
import * as math from './math.js'; // namespace import

console.log(add(2, 3));       // 5
console.log(multiply(2, 3));  // 6
```

**Enabling ESM in Node:**

- Use the `.mjs` file extension, **or**
- Add `"type": "module"` in `package.json` (then `.js` files are treated as ESM; use `.cjs` for CommonJS files).

```json
// package.json
{
  "type": "module"
}
```

**Key notes:**

- Imports are **asynchronous** and statically analyzed (enables tree-shaking).
- `import`/`export` statements must be top-level (not inside `if` blocks) — use dynamic `import()` for conditional loading.
- No `__dirname`/`__filename` by default — must derive from `import.meta.url`:

```js
import { fileURLToPath } from 'url';
import path from 'path';

const __filename = fileURLToPath(import.meta.url);
const __dirname = path.dirname(__filename);
```

- Can't freely mix `require()` and `import` in the same file.

---

### CJS vs ESM — Quick Comparison

|Feature|CommonJS|ES Modules|
|---|---|---|
|Syntax|`require()` / `module.exports`|`import` / `export`|
|Loading|Synchronous|Asynchronous|
|File extension|`.js`, `.cjs`|`.mjs`, or `.js` with `"type": "module"`|
|`__dirname`|Available by default|Must derive via `import.meta.url`|
|Top-level await|❌|✅|
|Tree-shaking|❌|✅|

## 2. File System Module (`fs`)

Built-in module for reading/writing/manipulating files and directories. Has **sync**, **callback (async)**, and **Promise-based** APIs.

```js
const fs = require('fs');
const fsPromises = require('fs/promises'); // Promise-based
```

### Reading Files

```js
// Synchronous — blocks execution
const data = fs.readFileSync('file.txt', 'utf8');
console.log(data);

// Asynchronous (callback)
fs.readFile('file.txt', 'utf8', (err, data) => {
  if (err) throw err;
  console.log(data);
});

// Asynchronous (Promise / async-await)
async function readMyFile() {
  const data = await fsPromises.readFile('file.txt', 'utf8');
  console.log(data);
}
```

### Writing Files

```js
// Sync
fs.writeFileSync('output.txt', 'Hello World');

// Async callback
fs.writeFile('output.txt', 'Hello World', (err) => {
  if (err) throw err;
  console.log('File written!');
});

// Append instead of overwrite
fs.appendFileSync('output.txt', '\nMore text');
```

### Other Common Operations

```js
// Check existence
fs.existsSync('file.txt'); // true/false

// Delete a file
fs.unlinkSync('file.txt');

// Create a directory
fs.mkdirSync('newFolder', { recursive: true }); // recursive for nested dirs

// Read directory contents
const files = fs.readdirSync('.');
console.log(files); // array of filenames

// Get file info/stats
const stats = fs.statSync('file.txt');
console.log(stats.isFile());       // true
console.log(stats.isDirectory());  // false
console.log(stats.size);           // bytes

// Rename/move a file
fs.renameSync('old.txt', 'new.txt');

// Watch a file for changes
fs.watch('file.txt', (eventType, filename) => {
  console.log(eventType, filename);
});
```

**Key notes:**

- Sync methods (`*Sync`) block the event loop — fine for scripts/startup, avoid in servers handling requests.
- Prefer `fs/promises` with `async/await` for cleaner async code in modern apps.
- Always handle errors (`try/catch` with promises, or the `err` param in callbacks) — file operations fail often (permissions, missing files, etc.).
- Encoding matters: without `'utf8'`, `readFile` returns a raw `Buffer`, not a string.

## 3. `fs.readFile()` vs `fs.readFileSync()`

Both read a file's contents, but they differ in **how** they run.

### `fs.readFile()` — Asynchronous

```js
const fs = require('fs');

console.log('Start');

fs.readFile('file.txt', 'utf8', (err, data) => {
  if (err) throw err;
  console.log('File data:', data);
});

console.log('End');
```

**Output order:**

```
Start
End
File data: ...
```

- **Non-blocking** — Node kicks off the read in the background and moves on to the next line immediately.
- Takes a **callback function** `(err, data)` that runs once the file is actually read.
- Rest of your program keeps executing while the file is being read.
- Preferred for servers/apps where you can't afford to freeze execution while waiting on disk I/O.

### `fs.readFileSync()` — Synchronous

```js
const fs = require('fs');

console.log('Start');

const data = fs.readFileSync('file.txt', 'utf8');
console.log('File data:', data);

console.log('End');
```

**Output order:**

```
Start
File data: ...
End
```

- **Blocking** — Node stops and waits right there until the file is fully read before moving to the next line.
- Returns the data **directly** (no callback needed) — but throws an error you must catch with `try/catch` if something goes wrong.
- Simpler to write, but freezes everything else (including incoming requests, if in a server) until it finishes.

### Side-by-Side

||`readFile`|`readFileSync`|
|---|---|---|
|Execution|Asynchronous (non-blocking)|Synchronous (blocking)|
|Returns data via|Callback `(err, data)`|Direct return value|
|Error handling|Check `err` in callback|`try/catch` block|
|Blocks event loop?|No|Yes|
|Best for|Servers, apps, anything handling multiple operations at once|One-off scripts, startup config loading, CLI tools|

### Rule of thumb

- Use **`readFileSync`** for quick scripts or app startup (e.g., loading a config file once when the server boots — blocking briefly there doesn't matter).
- Use **`readFile`** (or `fs/promises` with `async/await`) inside servers or anywhere responsiveness matters, since blocking would freeze the whole app for every other user/request while one file is being read.

**Bonus — the modern Promise-based version** (cleanest of both worlds: non-blocking _and_ simple to read):

```js
const fsPromises = require('fs/promises');

async function read() {
  const data = await fsPromises.readFile('file.txt', 'utf8');
  console.log(data);
}
```

## 4. Path Module

Built-in module for working with file and directory paths in a cross-platform way (handles `/` vs `\` differences between OSes).

```js
const path = require('path');
```

### Common Methods

```js
const filePath = '/users/john/documents/file.txt';

path.basename(filePath);            // 'file.txt'
path.basename(filePath, '.txt');    // 'file'  (strip extension)

path.dirname(filePath);             // '/users/john/documents'

path.extname(filePath);             // '.txt'

path.join('users', 'john', 'file.txt');
// 'users/john/file.txt' — safely joins segments with correct separator

path.resolve('folder', 'file.txt');
// Absolute path resolved from current working directory
// e.g. '/home/user/project/folder/file.txt'

path.parse(filePath);
// {
//   root: '/',
//   dir: '/users/john/documents',
//   base: 'file.txt',
//   ext: '.txt',
//   name: 'file'
// }

path.isAbsolute('/users/john');     // true
path.isAbsolute('john/docs');       // false

path.sep;                           // '/' on POSIX, '\' on Windows
```

### Practical Example (combining `fs` + `path`)

```js
const fs = require('fs');
const path = require('path');

// __dirname = directory of the current file
const filePath = path.join(__dirname, 'data', 'notes.txt');

if (fs.existsSync(filePath)) {
  const content = fs.readFileSync(filePath, 'utf8');
  console.log(content);
}
```

**Key notes:**

- **Always use `path.join()`/`path.resolve()`** instead of manually concatenating strings with `/` or `\` — avoids cross-platform bugs.
- `path.join()` just joins segments (relative result possible); `path.resolve()` always returns an absolute path.
- `__dirname` (CJS) gives the directory of the current module — commonly combined with `path.join` to build reliable paths regardless of where the script is run from.
