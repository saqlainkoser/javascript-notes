## 1. Introduction to MongoDB

### What is MongoDB?

**MongoDB** is a **NoSQL, document-oriented database**. Instead of tables and rows, it stores data as flexible **JSON-like documents** (stored internally as **BSON**, Binary JSON).

### SQL vs MongoDB terminology

|SQL (MySQL, PostgreSQL)|MongoDB|
|---|---|
|Database|Database|
|Table|**Collection**|
|Row|**Document**|
|Column|**Field**|
|Primary key|`_id`|
|JOIN|`$lookup` / `populate()`|
|Fixed schema|Flexible schema|

### A document

```json
{
  "_id": "65f1c2a8e4b0a1b2c3d4e5f6",
  "name": "Ali",
  "email": "ali@example.com",
  "age": 22,
  "skills": ["JavaScript", "Node.js"],
  "address": {
    "city": "Patiala",
    "state": "Punjab"
  },
  "createdAt": "2026-10-28T10:00:00Z"
}
```

Documents can contain **arrays** and **nested objects**, which removes many joins.

### Structure

```
MongoDB Server
└── Database  (shopdb)
    ├── Collection  (users)
    │   ├── Document { name: "Ali", ... }
    │   └── Document { name: "Sara", ... }
    └── Collection  (products)
        └── Document { name: "Laptop", ... }
```

### `_id` and ObjectId

Every document has a unique `_id`. If you don't provide one, MongoDB creates an **ObjectId**: a 12-byte value shown as 24 hex characters.

```
65f1c2a8e4b0a1b2c3d4e5f6
```

It contains a timestamp, so it is roughly time-ordered.

### Data types

|Type|Example|
|---|---|
|String|`"Ali"`|
|Number|`22`, `19.99`|
|Boolean|`true`|
|Date|`ISODate("2026-10-28")`|
|Array|`["a", "b"]`|
|Object (embedded document)|`{ city: "Patiala" }`|
|ObjectId|`ObjectId("65f1...")`|
|Null|`null`|

### SQL vs NoSQL

||SQL|MongoDB (NoSQL)|
|---|---|---|
|Schema|Strict, predefined|Flexible, evolves easily|
|Relationships|JOINs, foreign keys|Embedding or references|
|Scaling|Mostly vertical|Built for horizontal scaling|
|Best for|Complex transactions, strict structure|Fast-changing apps, JSON-heavy data|
|Query language|SQL|JSON-style query objects|

### Why MongoDB for the MERN stack?

- Data is JSON-like, matching JavaScript objects 1:1.
- Same language (JavaScript) from database to UI.
- Easy to start; flexible while the app is changing.

### Installing MongoDB locally (optional)

Install **MongoDB Community Server** and **MongoDB Compass** (a GUI) from mongodb.com. The default local address is:

```
mongodb://localhost:27017
```

Most beginners skip the local install and use **Atlas** (next section).

## 2. MongoDB Atlas (Cloud Database)

### What is Atlas?

**MongoDB Atlas** is MongoDB's official **cloud-hosted database service**. It has a free tier (M0) that is enough for learning and small projects, and nothing needs installing.

### Setup steps

**1. Create an account** Sign up at https://www.mongodb.com/cloud/atlas (Google sign-in works).

**2. Create a cluster**

- Click **Create** (or **Build a Database**)
- Choose the **Free (M0)** tier
- Pick a cloud provider (AWS) and the region closest to you
- Name the cluster (for example `Cluster0`)

**3. Create a database user**

- **Security > Database Access > Add New Database User**
- Authentication: **Password**
- Enter a username and a strong password (avoid special characters, or URL-encode them)
- Role: **Read and write to any database**

> This is a **database** user, not your Atlas login account.

**4. Allow network access**

- **Security > Network Access > Add IP Address**
- For learning: **Allow Access from Anywhere** (`0.0.0.0/0`)
- For production: whitelist only your server's IP

**5. Get the connection string**

- Cluster > **Connect > Drivers > Node.js**
- Copy the URI:

```
mongodb+srv://<username>:<password>@cluster0.abcde.mongodb.net/?retryWrites=true&w=majority
```

**6. Add the database name** Insert it before the `?`:

```
mongodb+srv://ali:MyPass123@cluster0.abcde.mongodb.net/shopdb?retryWrites=true&w=majority
```

MongoDB creates `shopdb` automatically when you first save data.

### Store it in `.env`

```env
MONGO_URI=mongodb+srv://ali:MyPass123@cluster0.abcde.mongodb.net/shopdb?retryWrites=true&w=majority
```

```
# .gitignore
.env
```

> Never commit the connection string. If it leaks, change the database user's password immediately.

### Connection string anatomy

```
mongodb+srv://  ali : MyPass123  @  cluster0.abcde.mongodb.net  /  shopdb  ?retryWrites=true
   protocol    user   password          host (cluster)          database      options
```

### Local vs Atlas

||Local|Atlas|
|---|---|---|
|Setup|Install software|Browser only|
|URI|`mongodb://localhost:27017/shopdb`|`mongodb+srv://...`|
|Access|Your machine only|Anywhere (with IP allow-list)|
|Backups|Manual|Available|
|Best for|Offline development|Learning, deployment|

### Compass (GUI)

Paste the same connection string into **MongoDB Compass** to browse collections, view documents, and run queries visually. Atlas also has a built-in **Browse Collections** view.

### Common connection errors

|Error|Cause and fix|
|---|---|
|`Authentication failed`|Wrong username/password; check the database user|
|`ENOTFOUND` / `querySrv ECONNREFUSED`|Network/DNS issue or typo in the host|
|`MongooseServerSelectionError`|IP not whitelisted in Network Access|
|Password with `@`, `#`, `/` breaks the URI|URL-encode it (`@` becomes `%40`)|
|Forgot database name|Add `/dbname` before `?`|

## 3. CRUD Operations (MongoDB Shell)

CRUD in MongoDB is done with methods on a **collection**. You can run these in **mongosh** (the MongoDB shell), Compass, or Atlas.

```bash
mongosh "mongodb+srv://cluster0.abcde.mongodb.net/shopdb" --username ali
```

### Basic shell commands

```js
show dbs                    // list databases
use shopdb                  // switch to (or create) a database
show collections            // list collections
db.dropDatabase()           // delete the current database
db.users.drop()             // delete a collection
```

### Create (Insert)

```js
// one document
db.users.insertOne({
  name: 'Ali',
  email: 'ali@example.com',
  age: 22,
  skills: ['JS', 'Node'],
});

// many documents
db.users.insertMany([
  { name: 'Sara', email: 'sara@example.com', age: 25 },
  { name: 'Zara', email: 'zara@example.com', age: 19 },
]);
```

### Read (Find)

```js
db.users.find()                              // all documents
db.users.find({ age: 22 })                   // filter
db.users.findOne({ email: 'ali@example.com' })   // first match
db.users.find({}, { name: 1, email: 1, _id: 0 }) // projection (choose fields)
db.users.countDocuments({ age: { $gt: 20 } })
```

**Modifiers**

```js
db.users.find().sort({ age: -1 })      // 1 = ascending, -1 = descending
db.users.find().limit(5)
db.users.find().skip(10).limit(5)      // pagination
db.users.find({ age: { $gte: 18 } }).sort({ name: 1 }).limit(10)
```

### Query operators

|Operator|Meaning|Example|
|---|---|---|
|`$eq`|Equal|`{ age: { $eq: 22 } }`|
|`$ne`|Not equal|`{ age: { $ne: 22 } }`|
|`$gt` / `$gte`|Greater than (or equal)|`{ age: { $gt: 18 } }`|
|`$lt` / `$lte`|Less than (or equal)|`{ age: { $lte: 30 } }`|
|`$in`|Value in list|`{ age: { $in: [19, 22] } }`|
|`$nin`|Value not in list|`{ age: { $nin: [19, 22] } }`|
|`$and`|All conditions|`{ $and: [{ age: { $gt: 18 } }, { name: 'Ali' }] }`|
|`$or`|Any condition|`{ $or: [{ age: 19 }, { age: 22 }] }`|
|`$not`|Negate|`{ age: { $not: { $gt: 30 } } }`|
|`$exists`|Field exists|`{ phone: { $exists: true } }`|
|`$regex`|Pattern match|`{ name: { $regex: '^A', $options: 'i' } }`|

```js
// age between 18 and 30
db.users.find({ age: { $gte: 18, $lte: 30 } })

// name starts with "A" OR age is under 20
db.users.find({ $or: [{ name: /^A/i }, { age: { $lt: 20 } }] })

// array contains a value
db.users.find({ skills: 'Node' })

// nested field (dot notation, quotes required)
db.users.find({ 'address.city': 'Patiala' })
```

### Update

```js
// update ONE document
db.users.updateOne(
  { email: 'ali@example.com' },           // filter
  { $set: { age: 23, city: 'Patiala' } }  // update operator
);

// update MANY documents
db.users.updateMany({ age: { $lt: 20 } }, { $set: { minor: true } });

// replace the whole document (except _id)
db.users.replaceOne({ name: 'Ali' }, { name: 'Ali Khan', age: 30 });

// upsert: update if found, insert if not
db.users.updateOne(
  { email: 'new@example.com' },
  { $set: { name: 'New User' } },
  { upsert: true }
);
```

**Update operators**

|Operator|Purpose|Example|
|---|---|---|
|`$set`|Set/change a field|`{ $set: { age: 23 } }`|
|`$unset`|Remove a field|`{ $unset: { phone: '' } }`|
|`$inc`|Increment a number|`{ $inc: { age: 1 } }`|
|`$mul`|Multiply|`{ $mul: { price: 1.1 } }`|
|`$rename`|Rename a field|`{ $rename: { name: 'fullName' } }`|
|`$push`|Add to an array|`{ $push: { skills: 'React' } }`|
|`$addToSet`|Add if not already present|`{ $addToSet: { skills: 'React' } }`|
|`$pull`|Remove from an array|`{ $pull: { skills: 'JS' } }`|
|`$pop`|Remove first/last array item|`{ $pop: { skills: 1 } }`|
|`$currentDate`|Set to the current date|`{ $currentDate: { updatedAt: true } }`|

> Forgetting `$set` replaces the document's fields. Always use update operators.

### Delete

```js
db.users.deleteOne({ email: 'ali@example.com' });
db.users.deleteMany({ age: { $lt: 18 } });
db.users.deleteMany({});     // deletes ALL documents (collection remains)
```

### Indexes (performance)

```js
db.users.createIndex({ email: 1 }, { unique: true });   // fast lookup + no duplicates
db.users.getIndexes();
```

Without an index MongoDB scans every document. Add indexes on fields you search, sort, or join on often.

### Aggregation (brief)

Pipelines process documents through stages:

```js
db.orders.aggregate([
  { $match: { status: 'completed' } },                       // filter
  { $group: { _id: '$userId', total: { $sum: '$amount' } } },// group + sum
  { $sort: { total: -1 } },                                  // sort
  { $limit: 5 },                                             // top 5
]);
```

Common stages: `$match`, `$group`, `$sort`, `$limit`, `$project`, `$lookup` (join), `$unwind`.

## 4. Mongoose

### What is Mongoose?

**Mongoose** is an **ODM** (Object Data Modeling) library for MongoDB and Node.js. MongoDB itself has no required structure; Mongoose adds **schemas, validation, relationships, and helpful methods** on top.

```
Express route  -->  Mongoose Model  -->  MongoDB
```

|Native MongoDB driver|Mongoose|
|---|---|
|Any shape of data|Defined schema|
|Manual validation|Built-in validation|
|Basic queries|Chainable queries, middleware, virtuals|
|No relationships helper|`populate()`|

### Install

```bash
npm install mongoose
```

### Connecting to the database

```js
// config/db.js
const mongoose = require('mongoose');

const connectDB = async () => {
  try {
    const conn = await mongoose.connect(process.env.MONGO_URI);
    console.log(`MongoDB connected: ${conn.connection.host}`);
  } catch (error) {
    console.error(`Connection error: ${error.message}`);
    process.exit(1);
  }
};

module.exports = connectDB;
```

```js
// index.js
require('dotenv').config();
const express = require('express');
const connectDB = require('./config/db');

const app = express();
app.use(express.json());

connectDB().then(() => {
  app.listen(process.env.PORT || 3000, () => console.log('Server running'));
});
```

Connection events:

```js
mongoose.connection.on('connected', () => console.log('Mongoose connected'));
mongoose.connection.on('error', (err) => console.error('Mongoose error:', err));
mongoose.connection.on('disconnected', () => console.log('Mongoose disconnected'));
```

## 5. Schemas

A **schema** defines the **structure** of documents in a collection: fields, types, defaults, and rules.

### Basic schema

```js
const mongoose = require('mongoose');

const userSchema = new mongoose.Schema({
  name: String,
  email: String,
  age: Number,
  isActive: Boolean,
  createdAt: Date,
});
```

### Schema types

|Type|Example|
|---|---|
|`String`|`name: String`|
|`Number`|`age: Number`|
|`Boolean`|`isActive: Boolean`|
|`Date`|`birthday: Date`|
|`Array`|`tags: [String]`|
|`ObjectId`|`author: mongoose.Schema.Types.ObjectId`|
|`Mixed`|`meta: mongoose.Schema.Types.Mixed` (anything)|
|`Buffer`|`file: Buffer`|
|Nested object|`address: { city: String, zip: String }`|

### Schema with options

```js
const userSchema = new mongoose.Schema(
  {
    name: {
      type: String,
      required: [true, 'Name is required'],
      trim: true,
      minlength: 2,
      maxlength: 50,
    },
    email: {
      type: String,
      required: true,
      unique: true,
      lowercase: true,
    },
    password: {
      type: String,
      required: true,
      minlength: 6,
      select: false,            // excluded from query results by default
    },
    age: {
      type: Number,
      min: 13,
      max: 120,
    },
    role: {
      type: String,
      enum: ['user', 'admin'],
      default: 'user',
    },
    skills: [String],
    address: {
      city: String,
      state: String,
    },
    isActive: {
      type: Boolean,
      default: true,
    },
  },
  { timestamps: true }          // adds createdAt and updatedAt automatically
);
```

### Common field options

|Option|Applies to|Purpose|
|---|---|---|
|`type`|All|Data type|
|`required`|All|Field must be present|
|`default`|All|Value when none provided|
|`unique`|All|Creates a unique index (not a validator)|
|`select`|All|Include/exclude from query results by default|
|`trim`|String|Remove surrounding spaces|
|`lowercase` / `uppercase`|String|Convert case|
|`minlength` / `maxlength`|String|Length limits|
|`match`|String|Regex pattern|
|`enum`|String|Allowed values|
|`min` / `max`|Number, Date|Range|
|`validate`|All|Custom validator|
|`index`|All|Create an index|
|`ref`|ObjectId|Which model it references (for populate)|

### Schema options

```js
new mongoose.Schema({ ... }, {
  timestamps: true,                 // createdAt, updatedAt
  versionKey: false,                // removes the __v field
  toJSON: { virtuals: true },       // include virtuals in JSON output
});
```

### Virtuals

Computed properties that are **not stored** in the database.

```js
userSchema.virtual('displayName').get(function () {
  return `${this.name} (${this.email})`;
});
```

### Instance methods and static methods

```js
// instance method: called on a document
userSchema.methods.isAdult = function () {
  return this.age >= 18;
};

// static method: called on the Model
userSchema.statics.findByEmail = function (email) {
  return this.findOne({ email: email.toLowerCase() });
};

// usage
const user = await User.findByEmail('ALI@example.com');
console.log(user.isAdult());
```

### Middleware (hooks)

Run code before or after an operation. A classic use: hash the password before saving.

```js
const bcrypt = require('bcrypt');

userSchema.pre('save', async function (next) {
  if (!this.isModified('password')) return next();   // only when password changed
  this.password = await bcrypt.hash(this.password, 10);
  next();
});

userSchema.methods.comparePassword = function (candidate) {
  return bcrypt.compare(candidate, this.password);
};
```

> In recent Mongoose versions an `async` hook doesn't need to call `next()`, but calling it is harmless.

### Indexes in schemas

```js
userSchema.index({ email: 1 });
postSchema.index({ title: 'text', content: 'text' });   // text search
postSchema.index({ author: 1, createdAt: -1 });         // compound index
```

## 6. Models

A **model** is a class built from a schema. It is the interface used to query and save documents in a collection.

```js
const User = mongoose.model('User', userSchema);
module.exports = User;
```

- `'User'` is the model name. Mongoose uses the **lowercase plural** as the collection name: `users`.
- Documents created from the model are **instances** with `.save()` and other methods.

### Model file example

```js
// models/User.js
const mongoose = require('mongoose');

const userSchema = new mongoose.Schema({
  name: { type: String, required: true, trim: true },
  email: { type: String, required: true, unique: true, lowercase: true },
  age: { type: Number, min: 13 },
}, { timestamps: true });

module.exports = mongoose.model('User', userSchema);
```

### Using a model

```js
const User = require('../models/User');

// create + save
const user = new User({ name: 'Ali', email: 'ali@example.com', age: 22 });
await user.save();

// or in one step
const user2 = await User.create({ name: 'Sara', email: 'sara@example.com', age: 25 });
```

### Suggested project structure

```
project/
├── config/
│   └── db.js
├── models/
│   ├── User.js
│   ├── Post.js
│   └── Comment.js
├── controllers/
├── routes/
├── middleware/
└── index.js
```

## 7. Mongoose CRUD

### Create

```js
// Model.create(): validates and saves
const user = await User.create({ name: 'Ali', email: 'ali@example.com' });

// many at once
await User.insertMany([
  { name: 'Sara', email: 'sara@example.com' },
  { name: 'Zara', email: 'zara@example.com' },
]);

// new + save
const u = new User({ name: 'Omar', email: 'omar@example.com' });
await u.save();
```

### Read

```js
await User.find();                                  // all
await User.find({ age: { $gte: 18 } });             // filter
await User.findOne({ email: 'ali@example.com' });   // first match
await User.findById('65f1c2a8e4b0a1b2c3d4e5f6');    // by _id
await User.countDocuments({ role: 'admin' });
await User.exists({ email: 'ali@example.com' });    // returns { _id } or null
```

**Chainable query helpers**

```js
const users = await User.find({ role: 'user' })
  .select('name email -_id')       // choose fields ("-field" excludes)
  .sort('-createdAt')              // newest first ("name" = ascending)
  .skip(20)
  .limit(10)
  .lean();                         // plain JS objects (faster, read-only)
```

|Helper|Purpose|
|---|---|
|`.select()`|Choose which fields to return|
|`.sort()`|Order results|
|`.skip()` / `.limit()`|Pagination|
|`.populate()`|Replace references with documents|
|`.lean()`|Return plain objects (no Mongoose methods), faster|

**Pagination**

```js
const page = Number(req.query.page) || 1;
const limit = Number(req.query.limit) || 10;

const [users, total] = await Promise.all([
  User.find().sort('-createdAt').skip((page - 1) * limit).limit(limit),
  User.countDocuments(),
]);

res.json({ page, pages: Math.ceil(total / limit), total, data: users });
```

**Search with regex**

```js
const { search } = req.query;
const users = await User.find({
  name: { $regex: search, $options: 'i' },     // case-insensitive
});
```

> If `search` comes from user input, escape regex special characters, or use a text index, to avoid slow or malicious patterns.

### Update

```js
// findByIdAndUpdate: returns the NEW document with { new: true }
const updated = await User.findByIdAndUpdate(
  req.params.id,
  { $set: { age: 23 } },
  { new: true, runValidators: true }
);

// updateOne / updateMany: return a result summary
await User.updateOne({ email: 'ali@example.com' }, { age: 24 });
await User.updateMany({ age: { $lt: 18 } }, { $set: { minor: true } });

// find, modify, save: runs full validation + pre('save') hooks
const user = await User.findById(id);
user.name = 'Ali Khan';
await user.save();
```

|Update option|Meaning|
|---|---|
|`new: true`|Return the updated document (default returns the old one)|
|`runValidators: true`|Apply schema validation on update (**off by default**)|
|`upsert: true`|Insert if no match|

> `findByIdAndUpdate` does **not** run `pre('save')` hooks. Use `find` + `save()` when you rely on them (for example password hashing).

### Delete

```js
await User.findByIdAndDelete(id);                 // returns the deleted document
await User.deleteOne({ email: 'ali@example.com' });
await User.deleteMany({ isActive: false });
```

### Using Mongoose in Express routes

```js
const express = require('express');
const mongoose = require('mongoose');
const User = require('../models/User');

const router = express.Router();

// GET /api/users
router.get('/', async (req, res, next) => {
  try {
    const users = await User.find().sort('-createdAt');
    res.json({ success: true, count: users.length, data: users });
  } catch (err) {
    next(err);
  }
});

// GET /api/users/:id
router.get('/:id', async (req, res, next) => {
  try {
    if (!mongoose.isValidObjectId(req.params.id)) {
      return res.status(400).json({ success: false, message: 'Invalid ID' });
    }

    const user = await User.findById(req.params.id);
    if (!user) {
      return res.status(404).json({ success: false, message: 'User not found' });
    }

    res.json({ success: true, data: user });
  } catch (err) {
    next(err);
  }
});

// POST /api/users
router.post('/', async (req, res, next) => {
  try {
    const user = await User.create(req.body);
    res.status(201).json({ success: true, data: user });
  } catch (err) {
    next(err);
  }
});

// PATCH /api/users/:id
router.patch('/:id', async (req, res, next) => {
  try {
    const user = await User.findByIdAndUpdate(req.params.id, req.body, {
      new: true,
      runValidators: true,
    });

    if (!user) {
      return res.status(404).json({ success: false, message: 'User not found' });
    }

    res.json({ success: true, data: user });
  } catch (err) {
    next(err);
  }
});

// DELETE /api/users/:id
router.delete('/:id', async (req, res, next) => {
  try {
    const user = await User.findByIdAndDelete(req.params.id);

    if (!user) {
      return res.status(404).json({ success: false, message: 'User not found' });
    }

    res.sendStatus(204);
  } catch (err) {
    next(err);
  }
});

module.exports = router;
```

> Passing `req.body` straight into `create` or `update` lets clients set fields like `role: 'admin'`. In real apps, pick only allowed fields: `const { name, email } = req.body;`.

## 8. Validation

### Built-in validators

```js
const productSchema = new mongoose.Schema({
  name: {
    type: String,
    required: [true, 'Product name is required'],
    trim: true,
    minlength: [3, 'Name must be at least 3 characters'],
    maxlength: [100, 'Name cannot exceed 100 characters'],
  },
  price: {
    type: Number,
    required: [true, 'Price is required'],
    min: [0, 'Price cannot be negative'],
  },
  category: {
    type: String,
    enum: {
      values: ['electronics', 'books', 'clothing'],
      message: '{VALUE} is not a valid category',
    },
  },
  sku: {
    type: String,
    match: [/^[A-Z]{3}-\d{4}$/, 'SKU must look like ABC-1234'],
  },
  stock: { type: Number, default: 0, min: 0 },
});
```

|Validator|For|Message format|
|---|---|---|
|`required`|All|`required: [true, 'msg']`|
|`min` / `max`|Number, Date|`min: [0, 'msg']`|
|`minlength` / `maxlength`|String|`minlength: [3, 'msg']`|
|`enum`|String|`enum: { values: [...], message: '...' }`|
|`match`|String|`match: [/regex/, 'msg']`|

### Custom validators

```js
const userSchema = new mongoose.Schema({
  email: {
    type: String,
    required: true,
    validate: {
      validator: (v) => /^\S+@\S+\.\S+$/.test(v),
      message: (props) => `${props.value} is not a valid email`,
    },
  },
  confirmedAge: {
    type: Number,
    validate: {
      validator: Number.isInteger,
      message: 'Age must be a whole number',
    },
  },
});
```

Async validator (for example checking uniqueness):

```js
username: {
  type: String,
  validate: {
    validator: async function (value) {
      const exists = await mongoose.models.User.exists({ username: value });
      return !exists;
    },
    message: 'Username is already taken',
  },
},
```

### `unique` is not a validator

`unique: true` creates a **database index**. A duplicate throws a MongoDB error (`code 11000`), not a `ValidationError`. Handle it in your error middleware:

```js
if (err.code === 11000) {
  const field = Object.keys(err.keyValue)[0];
  return res.status(409).json({ success: false, message: `${field} already exists` });
}
```

### Handling validation errors

```js
try {
  await Product.create({ name: 'A', price: -5 });
} catch (err) {
  if (err.name === 'ValidationError') {
    const messages = Object.values(err.errors).map((e) => e.message);
    console.log(messages);
    // [ 'Name must be at least 3 characters', 'Price cannot be negative' ]
  }
}
```

Central error handler (from note 18):

```js
if (err.name === 'ValidationError') {
  return res.status(400).json({
    success: false,
    errors: Object.values(err.errors).map((e) => ({ field: e.path, message: e.message })),
  });
}

if (err.name === 'CastError') {   // invalid ObjectId
  return res.status(400).json({ success: false, message: `Invalid ${err.path}: ${err.value}` });
}
```

### Validation on updates

Validators run on `create()` and `save()` automatically, but **not** on `findByIdAndUpdate` / `updateOne` unless you pass `runValidators: true`.

```js
await Product.findByIdAndUpdate(id, { price: -10 }, { runValidators: true });  // now rejected
```

### Manual validation

```js
const product = new Product({ name: 'Mouse' });
const error = product.validateSync();      // sync, returns ValidationError or undefined
await product.validate();                  // async, throws on error
```

## 9. Populate (Relationships)

### Relationships in MongoDB

There are two ways to model related data.

|Approach|Description|Use when|
|---|---|---|
|**Embedding**|Store related data inside the document|Data is read together, small, and rarely shared (address, tags)|
|**Referencing**|Store the related document's `_id`|Data is large, shared, or changes independently (users, posts)|

**Embedded**

```js
{
  name: 'Ali',
  address: { city: 'Patiala', state: 'Punjab' }
}
```

**Referenced**

```js
{
  title: 'My first post',
  author: ObjectId('65f1c2a8e4b0a1b2c3d4e5f6')     // points to a user
}
```

### Defining a reference with `ref`

```js
// models/Post.js
const postSchema = new mongoose.Schema({
  title: { type: String, required: true },
  content: String,
  author: {
    type: mongoose.Schema.Types.ObjectId,
    ref: 'User',                                  // name of the User model
    required: true,
  },
  likes: [{ type: mongoose.Schema.Types.ObjectId, ref: 'User' }],   // array of references
}, { timestamps: true });

module.exports = mongoose.model('Post', postSchema);
```

### What is `populate()`?

Without populate, `author` is just an ID. **`populate()`** replaces that ID with the full document (like a SQL JOIN, performed by Mongoose with an extra query).

```js
const post = await Post.findById(id);
console.log(post.author);
// 65f1c2a8e4b0a1b2c3d4e5f6

const populated = await Post.findById(id).populate('author');
console.log(populated.author);
// { _id: '65f1...', name: 'Ali', email: 'ali@example.com', ... }
```

### Choosing fields

```js
await Post.find().populate('author', 'name email');       // only name and email (+ _id)
await Post.find().populate('author', 'name -_id');        // name only, no _id
await Post.find().populate({ path: 'author', select: 'name email' });
```

> Always limit the fields to avoid leaking data (such as password hashes) in responses.

### Populating multiple paths

```js
await Post.find()
  .populate('author', 'name')
  .populate('likes', 'name');
```

### Filtering and options inside populate

```js
await Post.find().populate({
  path: 'likes',
  match: { isActive: true },           // only active users
  select: 'name',
  options: { limit: 5, sort: { name: 1 } },
});
```

### Nested (deep) populate

```js
// Comment -> Post -> Author
await Comment.find().populate({
  path: 'post',
  select: 'title author',
  populate: { path: 'author', select: 'name' },
});
```

### Comment model (one-to-many)

```js
// models/Comment.js
const commentSchema = new mongoose.Schema({
  text: { type: String, required: true },
  post: { type: mongoose.Schema.Types.ObjectId, ref: 'Post', required: true },
  user: { type: mongoose.Schema.Types.ObjectId, ref: 'User', required: true },
}, { timestamps: true });

module.exports = mongoose.model('Comment', commentSchema);
```

```js
const comments = await Comment.find({ post: postId })
  .populate('user', 'name')
  .sort('-createdAt');
```

### Virtual populate (reverse relationship)

Show a post's comments **without** storing comment IDs on the post.

```js
// in models/Post.js
postSchema.virtual('comments', {
  ref: 'Comment',
  localField: '_id',       // field on Post
  foreignField: 'post',    // field on Comment that points back
});

postSchema.set('toJSON', { virtuals: true });
postSchema.set('toObject', { virtuals: true });

// usage
const post = await Post.findById(id).populate('comments');
```

### Populating after the fact

```js
const post = await Post.findById(id);
await post.populate('author', 'name');         // populate an existing document
```

### Populate in an Express route

```js
// GET /api/posts: list with author names
router.get('/', async (req, res, next) => {
  try {
    const posts = await Post.find()
      .populate('author', 'name email')
      .sort('-createdAt');

    res.json({ success: true, count: posts.length, data: posts });
  } catch (err) {
    next(err);
  }
});

// POST /api/posts: author comes from the logged-in user (note 18)
router.post('/', protect, async (req, res, next) => {
  try {
    const { title, content } = req.body;
    const post = await Post.create({ title, content, author: req.user._id });
    res.status(201).json({ success: true, data: post });
  } catch (err) {
    next(err);
  }
});
```

Example response:

```json
{
  "success": true,
  "count": 1,
  "data": [
    {
      "_id": "66a1...",
      "title": "My first post",
      "content": "Hello MongoDB!",
      "author": { "_id": "65f1...", "name": "Ali", "email": "ali@example.com" },
      "createdAt": "2026-10-28T10:00:00.000Z"
    }
  ]

```

### Populate vs `$lookup`

||`populate()`|`$lookup` (aggregation)|
|---|---|---|
|Where it runs|Mongoose (extra queries)|Inside MongoDB (single query)|
|Ease|Very easy|More verbose|
|Best for|Typical app queries|Heavy reporting and large joins|

### `routes/postRoutes.js`

```js
const express = require('express');
const mongoose = require('mongoose');
const Post = require('../models/Post');
const Comment = require('../models/Comment');

const router = express.Router();

// CREATE: POST /api/posts
router.post('/', async (req, res, next) => {
  try {
    const { title, content, tags, author } = req.body;     // pick allowed fields only
    const post = await Post.create({ title, content, tags, author });
    res.status(201).json({ success: true, data: post });
  } catch (err) {
    next(err);
  }
});

// READ ALL: GET /api/posts?tag=node&page=1&limit=5
router.get('/', async (req, res, next) => {
  try {
    const { tag, status = 'published', page = 1, limit = 5 } = req.query;

    const filter = { status };
    if (tag) filter.tags = tag.toLowerCase();

    const [posts, total] = await Promise.all([
      Post.find(filter)
        .populate('author', 'name email')
        .sort('-createdAt')
        .skip((Number(page) - 1) * Number(limit))
        .limit(Number(limit)),
      Post.countDocuments(filter),
    ]);

    res.json({
      success: true,
      total,
      page: Number(page),
      pages: Math.ceil(total / Number(limit)),
      data: posts,
    });
  } catch (err) {
    next(err);
  }
});

// READ ONE: GET /api/posts/:id (with author + comments)
router.get('/:id', async (req, res, next) => {
  try {
    if (!mongoose.isValidObjectId(req.params.id)) {
      return res.status(400).json({ success: false, message: 'Invalid post ID' });
    }

    const post = await Post.findById(req.params.id)
      .populate('author', 'name email')
      .populate({
        path: 'comments',
        populate: { path: 'user', select: 'name' },
      });

    if (!post) return res.status(404).json({ success: false, message: 'Post not found' });

    res.json({ success: true, data: post });
  } catch (err) {
    next(err);
  }
});

// UPDATE: PATCH /api/posts/:id
router.patch('/:id', async (req, res, next) => {
  try {
    const { title, content, tags, status } = req.body;

    const post = await Post.findByIdAndUpdate(
      req.params.id,
      { title, content, tags, status },
      { new: true, runValidators: true, omitUndefined: true }
    ).populate('author', 'name');

    if (!post) return res.status(404).json({ success: false, message: 'Post not found' });

    res.json({ success: true, data: post });
  } catch (err) {
    next(err);
  }
});

// DELETE: DELETE /api/posts/:id (also removes its comments)
router.delete('/:id', async (req, res, next) => {
  try {
    const post = await Post.findByIdAndDelete(req.params.id);
    if (!post) return res.status(404).json({ success: false, message: 'Post not found' });

    await Comment.deleteMany({ post: post._id });

    res.sendStatus(204);
  } catch (err) {
    next(err);
  }
});

// ADD COMMENT: POST /api/posts/:id/comments
router.post('/:id/comments', async (req, res, next) => {
  try {
    const post = await Post.exists({ _id: req.params.id });
    if (!post) return res.status(404).json({ success: false, message: 'Post not found' });

    const comment = await Comment.create({
      text: req.body.text,
      user: req.body.user,
      post: req.params.id,
    });

    res.status(201).json({ success: true, data: comment });
  } catch (err) {
    next(err);
  }
});

module.exports = router;
```

## 11. Quick Reference

### Mongoose cheat sheet

```js
// Connect
await mongoose.connect(process.env.MONGO_URI);

// Schema + Model
const schema = new mongoose.Schema({ name: { type: String, required: true } }, { timestamps: true });
const Model = mongoose.model('Name', schema);

// Create
await Model.create({ name: 'x' });

// Read
await Model.find(filter).select('a b').sort('-createdAt').skip(0).limit(10).populate('ref', 'name');
await Model.findById(id);
await Model.findOne({ email });

// Update
await Model.findByIdAndUpdate(id, data, { new: true, runValidators: true });

// Delete
await Model.findByIdAndDelete(id);
await Model.deleteMany({ ... });

// Relationship
{ author: { type: mongoose.Schema.Types.ObjectId, ref: 'User' } }
```

### Mongo shell vs Mongoose

|Operation|Shell|Mongoose|
|---|---|---|
|Insert one|`db.users.insertOne({})`|`User.create({})`|
|Find all|`db.users.find()`|`User.find()`|
|Find one|`db.users.findOne({})`|`User.findOne({})`|
|By id|`db.users.findOne({ _id })`|`User.findById(id)`|
|Update one|`db.users.updateOne(f, u)`|`User.updateOne(f, u)` / `findByIdAndUpdate`|
|Delete one|`db.users.deleteOne(f)`|`User.deleteOne(f)` / `findByIdAndDelete`|
|Count|`db.users.countDocuments()`|`User.countDocuments()`|

### Common mistakes

|Mistake|Fix|
|---|---|
|Atlas `Authentication failed`|Check the **database user** credentials and URL-encode special characters|
|`MongooseServerSelectionError`|Add your IP in **Network Access** (or `0.0.0.0/0` for learning)|
|No database name in the URI|Add `/dbname` before `?`|
|Committing the connection string|Keep it in `.env` and add `.env` to `.gitignore`|
|Not awaiting queries (`User.find()` without `await`)|You get a Query object, not data; use `await`|
|`findByIdAndUpdate` returns the old document|Pass `{ new: true }`|
|Validators not running on update|Pass `{ runValidators: true }`|
|Expecting `unique` to validate|It's an index; handle error code `11000`|
|Invalid ObjectId crashes (`CastError`)|Check `mongoose.isValidObjectId(id)` or handle `CastError`|
|`findByIdAndUpdate` skipping `pre('save')` hooks|Use `find` + modify + `save()`|
|Returning password hashes|`select: false` in the schema; limit fields in `populate`|
|`populate` does nothing|Missing `ref`, wrong model name, or the path isn't an ObjectId|
|Passing `req.body` directly to `create`|Pick allowed fields to prevent mass assignment|
|Using `ref: 'users'`|`ref` uses the **model name** (`'User'`), not the collection name|
|Server starts before DB connects|Connect first, then call `app.listen()`|
|Large unbounded `find()`|Paginate with `skip` and `limit`|

### Summary

- **MongoDB** stores flexible JSON-like **documents** in **collections**; relationships use embedding or references.
- **Atlas** is the free cloud host: create a cluster, a database user, allow your IP, and use the `mongodb+srv://` URI from `.env`.
- **CRUD** uses `insertOne/Many`, `find`, `updateOne/Many` (with `$set`, `$inc`, `$push`...), and `deleteOne/Many`.
- **Mongoose** adds **schemas** (structure), **models** (the query interface), built-in and custom **validation**, hooks, virtuals, and **populate** to resolve references into full documents.
